# Workflows 面板升级故障与修复

日期：2026-10-13。修复版本：0.2.1。

## 故障证据

0.2.0 从 GitHub 安装成功，独立启动的安装包有 15 个工具且能读取面板资源，但正在运行的 Codex App 仍持有 0.1.4 MCP 进程和内部会话。

本机主日志显示两类错误：旧资源地址读取已被升级删除的 0.1.4 `runtime/panel.html` 时返回 ENOENT；新界面地址 `ui://workflows/panel/0.2.0.html` 交给旧服务时返回 `-32602 Resource not found`。原生页面的 `htmlByteLength=undefined`，说明 HTML 没有送达，还没有进入界面脚本或握手阶段。原始日志和会话标识未加入仓库。

## 修复

- 新入口固定为 `ui://workflows/panel.html`，后续发布不随版本变更地址。
- 保留 0.1.4、0.2.0、0.2.1 历史地址别名，均返回当前服务对应的面板。
- 服务启动时预读 HTML；运行期间即使安装器删除旧目录，面板也能继续读取。
- 能力查询与面板工具结果返回实际运行版本，区分安装包和正在连接的服务。

真实 stdio 冒烟先启动服务，再删除其临时面板文件；固定地址和全部别名仍返回一致的 HTML 与元数据。相关执行、持久化和面板测试一并通过。

这些改动保护 0.2.1 及后续服务的升级过程，不能替换已经驻留内存的 0.1.4 代码。首次跨到修复版本仍需完整退出并重新打开 Codex，让聊天与插件内部会话加载新服务；只点击失败页面的重试不会清空旧服务。

当前工具不允许直接自动操作 Codex 原生界面，因此完整宿主重新加载与页面显示仍需在用户重启后核对，不把独立协议验证当作原生验收。
