# 原创设计指导升级与验证边界

更新日期：2026-10-17。本文记录指导层的实现范围，不作为发布 Skill 的前置资料。

已完成任务/投入路由、可组合专业规则、20 张按需载入的原创方向卡，以及图层与代码介质的独立说明。原有六个方向 ID 和 `getDesignGuidance` / `buildArtDirectionPrompt` / `medium: 'layers' | 'code'` 接口保留。

这些变化增加了模型可用的设计决策信息。静态与真实交互达到 Claude Design 对标水平，仍需在相同任务、组件、素材和验收标准下验证；方向数量和协议测试不构成这个结论。

## 实际实现

| 能力 | 实现位置与行为 | 本次证据 |
| --- | --- | --- |
| 主任务路由 | `src/art-direction.ts` 区分落地页、工作台、数据、编辑、品牌、组件、原型、对比、机制图解及综合任务 | 显式 `taskType` 优先；自然语言规则辅助推断，不声称完整语义理解 |
| 专业规则组合 | 主任务保持不变，图表、组件库和机制图解按内容补规则 | 含图表且复用组件的落地页仍是落地页，同时加入数据与组件合同 |
| 投入与范围 | 快改、标准、探索、精修；新设计、局改、系统级调整分别处理 | 局改锁定品牌/无关区域，新建页面可继续继承品牌，跨页面调整按系统范围识别 |
| 设计决策矩阵 | 主体特异信息、字体、密度/网格、颜色、图像、动态、诚实内容、状态与视口 | 要求实际内容和代码决策，不以风格标签替代任务 |
| 方向卡 | 保留六个 ID，增至 20 张；每张有用途、避免场景、构图、字体角色、色彩角色和关键细节 | 只有指定 `directionId` 才载入对应完整卡片；默认仅基础规则和摘要 |
| 探索构图 | 返回 2–3 个不同构图的说明；指定方向时保持同一方向语义 | 不是随机换色，不强制停轮；局改候选也限制在授权区域 |
| 介质合同 | 图层说明 `navigate/url/toggle` 的边界；代码说明真实事件、状态与响应式 CSS | 代码指导不会继承旧场景图的交互限制 |
| 审阅建议 | 按影响与任务设置有限检查范围，区分渲染、模型看图、交互和源码应用 | 无真实画面不能报告视觉验收；预算结束需保留问题，而非制造高分 |
| 发布参考 | `skills/design/references/art-direction.md` 与 `direction-cards.md` | 传递文件引用与方向锚均位于当前 Skill；外部来源只作可选署名说明 |

`reviewBudget` 是指导层的建议元数据，本次没有修改执行器的回合调度。调用者应结合实际超时、模型能力和已有证据执行，不得把该字段报告成已经完成的检查。

当前 MCP 输入 schema 和 UI 没有由本任务修改。新增 `taskType`、`effort`、`scope`、`existingSystem` 等是 TypeScript 构造器的可选输入；工具仅传入已有 `brief/directionId` 时仍可工作并返回路由结果，不代表宿主界面已为每项新增专用控制。

## 与参考研究的映射

来源分析见 [Claude Code REA 研究](claude-code-design-guidance-rea.md) 与 [Huashu / OpenDesign 研究](open-design-references.md)。发布 Skill 不引用这两份开发文档。

| 参考中得到的具体问题 | 本次原创规则如何处理 | 仍未实现或未证明 |
| --- | --- | --- |
| Claude 基础指导先判任务处理强度，再用主体形成差异 | 主任务、投入和主体信息分开决定，方向卡只是候选材料 | 不复制其 Skill；云端实时 Design prompt 仍未获得 |
| Claude 数据指导以数据任务和可检验编码组织专业知识 | 数据任务与附加数据规则要求来源、单位、形态、尺度、稳定系列和替代读取 | 没有在本次新增数值色板验证器、数据自动核对或图形专家执行工具 |
| Claude 组件消费依赖真实 API、provider、token、字体与样式闭包 | 组件任务明确要求同版本可运行合同，不猜类名和 prop | 没有在本次实现任意组件库的自动提取、依赖闭包构建或参考保真比对 |
| Huashu 的中文排印、品牌输入与素材限制 | 字体角色、中文/混排/行高、真实资产和品牌保留进入共同矩阵 | 模型得到规则不证明实际字形正确；仍需真实渲染和字体加载证据 |
| Huashu 用同一内容比较不同视觉方向 | 探索说明比较构图、阅读顺序、密度和主行动；不只更换颜色 | 没有把其 HTML/截图模板复制入包，也未据此完成本项目 20 个视觉样例 |
| OpenDesign 将任务、craft、模板、设计系统分工 | 指导区分共同规则、主任务、附加专业规则和单张方向卡；默认只加载需要的信息 | 这是本地构造器组合，未实现 OpenDesign 的完整安装目录、插件发现或独立 craft 加载协议 |
| 各库中的“文件写完即结束”、假随机输出与来源不明示例 | 要求真实检查、诚实内容和可追溯结果，不继承假执行或强制营销结构 | 没有因为指导文本更丰富而声称生成质量已超越参考产品 |

所有新增规则和卡片均为本项目重新组织的原创说明；没有复制第三方完整 Skill、验证脚本、模板或素材。实际引入第三方文件时仍需逐项确认来源、许可与随包声明。

## 验证结果

- 新增 `tests/art-direction.test.ts`，9 项通过：接口兼容、路由优先与专业组合、既有品牌/局改保留、投入范围、探索构图差异、介质边界、按需载入预算、包内引用和错误输入。
- 与图层和代码生成协议 fixture 联合检查共 38 项通过；这些是受控测试，不是实际模型的艺术效果验收。
- TypeScript 类型检查通过。
- 默认基础指导约 2011 个 JavaScript 字符；显式 `editorial` 单卡约 1408 个字符，均不含用户 brief/既有系统输入。这是文本长度，不是 token 或费用保证。

本轮未发送真实模型请求，未为 20 个方向逐一生成案例，未执行静态/交互全面对标，也未启动 Motion 开发。下一步应选相同内容和真实组件完成代表任务，保留源码、修订、宽窄视口、关键动作回读、无关源码保留及剩余问题，之后再决定指导与运行时的下一项改进。
