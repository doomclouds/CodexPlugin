## 已确认的类型入口

恢复的 `uf` 声明接受 `Motion` 与 `Animation` 两个标题。`df` 从动态发现结果的 `motion_type` 读取标题和 `type_url`，规范化后匹配标题；缺少可用地址或匹配标题时不生成这条入口指导。

该指导表达的顺序是：针对可观看的短动画、演示或动态图形，选当前发现的类型，以标题创建一个初始不含文件的 Artifact，再获取创建结果携带的指令。**这些是分析对象中的指令数据，不是我们本次会执行的命令。**

这个入口证明类型驱动的 Motion 工作流存在于该样本，不证明客户端包含一套可直接调用的完整本地时间轴、关键帧或编码器。此次所选别名模块明确出现 Design/Slides 的命令注册；不能由此推断全部程序不存在其他 Motion 入口。

## 对本插件的有效启发

可吸收的是“发现真实能力合同—读取专用创作指导与资源—修改真实工程—检查真实输出—明确失败和恢复”的机制。Motion 的叙事、镜头、时间与音频规则必须来自独立可用的本地实现及素材闭包，不能由一个 Motion 名称或通用 React 预览冒充。

目前未确认 Motion Artifact 的实际专用 Skill、场景/时间轴结构、渲染引擎、音频处理、帧率和格式合同。这些仍是下一步取证目标。实际预览、视频渲染和完整作品质量需分别证明；不能将通用截图链或相邻视频模板直接归为 Motion。
