# 静态 Design 质量门槛与 Motion 入口

更新日期：2026-10-17。**当前结论：未完成静态产品对标验收，不能宣称已达到或超越三方，也未满足 Motion 开发入口。**

用户要求先深挖 Claude Design、Huashu Design、OpenDesign 的静态设计与实际使用，再考虑 Motion。本文件把该顺序变成可测门槛。下面的样本规模、比较方法与通过条件是本项目建议采用的验收方案，不是已经取得的成绩；执行前应固定方案，不能看到结果后只挑有利样本。

“静态 Design”包括可运行、可编辑的页面和原型。按钮、输入、组件状态、源码修改、评论、版本与交付都属于当前阶段；不能因为尚未开始 Motion，就把它们降成静态截图。

研发同时沿两条线推进：同域竞品按“问题—机制—证据—本地适配”吸收优势；跨出版、建筑、工业设计、数据叙事、影视与导视提出可检验假设。每条探索绑定 brief、适用/避免条件、对照与反例，保留失败，不以样式抄袭或风格拼贴替代改进。执行方法见 [研发与灵感研究原则](design-research-principles.md)，其中候选方向尚未表示完成采样。

## 1. 证据等级与现状

| 证据 | 能证明什么 | 不能替代什么 |
|---|---|---|
| 源码、资源、协议与许可研究 | 方法、接口、包含的文件及能力边界 | 实际账号开放、真实作品质量、用户操作通过 |
| 单元测试与协议 fixture | 被覆盖的解析、并发、任务状态分支 | 真实模型、真实浏览器与原生宿主 |
| 开发预览中的真实操作与源文件回读 | 该运行包、数据目录和浏览器路径的行为 | Codex / ChatGPT 原生面板，或其他版本 |
| 原生宿主实测 | 该宿主与版本的加载、消息、选择和导出体验 | 其他宿主或全部任务 |
| 同 brief、多样本的可比作品与评审 | 声明范围内的相对表现 | 所有场景、所有模型或长期稳定性的普遍结论 |

已完成的三方研究见 [Claude 工作流研究](claude-design-rea-workflow.md)、[Claude 设计指导研究](claude-code-design-guidance-rea.md)、[Huashu 与 OpenDesign 参考研究](open-design-references.md)。这些文档明确保留云端未知、目录条目、依赖、许可和未运行案例的边界。

当前操作用例见 [CodeProject IAB 验证清单](verification/code-ui-checklist.md)，其中结果仍须由实际执行记录补齐。已有局部技术验证不能自动把下列整体验收门槛改为通过。新增风格、提示词、工具或模板数量也不改变门槛状态。

## 2. 同 brief、多样本的比较设计

### 固定任务与输入

首批覆盖四类真实任务，每类固定同一份内容、数据、图片、组件、修改要求与交付要求：

| Brief | 必含内容 | 重点区分的能力 |
|---|---|---|
| A：中文知识与技术文档 | 中文长标题、中西混排、代码、表格、目录、复制或搜索任务 | 阅读层级、中文排印、长内容导航、真实控件 |
| B：专业运营工作台 | 可核对的小型数据集、单位与时间范围、筛选/排序、详情、空与错误状态 | 密度、数据诚实、扫描效率、状态与恢复 |
| C：有真实品牌素材的产品页面 | 有来源的品牌与产品图、具体文案、主行动、表单、手机布局 | 内容特异性、素材使用、品牌一致性、响应式 |
| D：已有组件项目的连续改稿 | 同一代码基线、组件及样式依赖、手动改动、定位评论、导出需求 | 真实组件复用、局部保留、编辑往返与工程交付 |

受控测试数据要标明为验收数据，并提供预期值；不能虚构客户规模、营业额或证言来提高视觉评分。各工具获得同样可使用的素材与说明，缺失输入不能由某一方悄悄补造。

### 样本与公平性

1. 每个 brief 对本项目和每个可实际使用的基准各做 **3 次独立样本**。四个 brief 对每一基准形成 12 组配对，不只展示最好一次。
2. 记录产品/Skill 提交、模型与可见配置、宿主、时间、输入、实际生成及修改次数。模型条件无法一致时单列差异，结论限定为完整产品体验，不能归因于插件单项能力。
3. 固定首次交付和一次相同修改任务的时间/操作预算；分别记录首稿与改稿结果。超时、缺文件、白屏、素材缺失和失败均保留，不移出分母。
4. 三方必须通过其真实可用路径取得结果。Claude 只有静态恢复资料、某 Skill 只有目录指针或上游未取得时，对应单元格记“未实测”，不能模拟其产物。
5. 视觉评审隐藏产物来源、打散顺序；在评审前固定问题与评价依据。评审者数量和角色如实记录，模型点评与用户偏好分别列出，不能伪装成独立人工评审。
6. 保存每个样本的源码/版本、宽窄画面、实际操作结果、未完成项与失败原因。主观评价只用于比较设计判断，不能冒充可访问性或功能检测。

### 如何表述“超越”

建议采用的限定门槛：本项目先通过第 3 节全部硬门槛；随后对每个基准的 12 组可比样本，至少 **9 组**在预先固定的评审流程中获得本项目多数偏好，且没有任何一类 brief 的主任务成功率低于该基准。连续修改的错误数、恢复操作与总耗时一并报告，不能用更好看的首屏掩盖改稿失败。

这是项目的比较准则，不是统计显著性或行业认证。即使达到，也只能写“在这四类任务、这些版本与模型条件下表现更好”。缺少实际基准、多样本或可核对评审时，只能声明具体功能/任务通过，不能写“已超越 Claude Design / Huashu / OpenDesign”。

## 3. 静态产品硬门槛

所有门槛当前均为**待验收**。通过记录须关联运行包版本/哈希、项目 ID 与修订、操作路径、源码回读及实际图像。若存在丢失改动、错误写入对象、不可恢复版本冲突、主流程不可用等阻断问题，不得以视觉平均分抵消。宿主范围以用户确定和版本实际声明的支持范围为准：本地 Codex 是当前必验路径；ChatGPT 原生宿主仅在声明支持时单独验收，未支持就明确标注，不能把本地任务自动扩大为远端服务建设。

| 门槛 | 可测通过条件 | 必留证据 |
|---|---|---|
| G1 内容与概念 | 页面主张、顺序、图文关系来自具体受众和内容；四类 brief 不产出换标题即互换的同一模板；品牌/锁定内容不被擅自覆盖 | brief、决策说明、全部样本图、用户/评审反馈 |
| G2 中文版式与控件可读性 | 在指定宽窄尺寸中无缺字、标题碰撞、正文遮挡、溢出；字体真实加载或明确回退；正常/选中/禁用/焦点/展开状态文字均可读，覆盖原生 select/option | 字体/资源记录、长文本测试、状态截图与对比检查 |
| G3 素材真实且完整 | 实际使用的图像、图标、字体、logo 与数据有可追溯来源和使用/分发依据；没有把占位图、假证言、假统计当成完成；所有需要分发的依赖实际进入交付 | 素材清单、来源/许可、文件哈希、缺失或替代说明 |
| G4 响应式与视觉组织 | 同一源码在约 375/390、768、1440 宽度运行；窄屏保留主任务与阅读顺序；无非必要横向滚动、隐藏主行动或桌面等比缩小；主题按声明范围检查 | 同修订视口图、真实 viewport、溢出与布局观察 |
| G5 真实交互与组件 | 主按钮、表单、筛选、导航、对话框和组件状态完成声明的任务；加载/空/错误/正常/边界按实际场景覆盖；无后端时明确本地示例；外部组件的脚本、样式、字体与资产依赖齐全 | 操作前后值、运行错误、源文件与组件依赖、失败恢复 |
| G6 连续修改与状态 | 完成至少 5 步交替修改：用户源码改、元素改、当前模型局部改、评论改稿、撤销重做；无关区域、手动改动、稳定身份与评论不丢；无源码变化的面板操作/同修订轮询不重置原型输入状态 | 每步修订/hash、差异、评论锚、history 与运行状态前后值 |
| G7 冲突、取消与恢复 | 旧 hash/revision 明确拒绝，草稿与提案保留；任务完成不冒充已应用；取消读到真实停止；切项目不误写/误应用/覆盖当前视图；刷新后持久项目正确 | 并发负例、worker 状态、A/B 项目回读、恢复记录 |
| G8 可编辑工程与导出 | HTML 真正可运行，源码包保留 HTML/React/TSX/CSS 与素材；在隔离目录重新打开可继续编辑；PNG/PDF 为实际渲染；导出与当前修订一致，缺依赖时不报成功 | 导出文件、包内引用检查、隔离运行图、导入/再编辑记录 |
| G9 宿主与模型路径 | 当前聊天是默认路径；选中源与评论真的进入同一聊天或明确复制回退；独立 Codex 使用真实目录/登录和分阶段验证；已声明支持的宿主分别加载新版本、打开编辑器、选择、修改和导出 | 本地 Codex 必验；其他声明支持的宿主各自记录；协议、推理、面板结果分列 |

G6 要分别记录两种状态：**持久设计状态**（源码、手动改动、评论、版本）与**临时原型状态**（输入、勾选、滚动、展开）。源码重编译后是否支持临时状态恢复应单独测试、实现或明确限制；不能用持久源码正确来声称运行中状态也无损保留。若改动无关区域却静默清空用户正在试用的数据，应记为连续修改的未完成项。

## 5. Motion 入口门槛

**当前不得把 Motion 标为启动或已通过。** 先完成以下条件，才进入 Motion 的专门产品定义、源码研究和实现排期：

1. G1–G9 有可审查的静态验收记录，主任务和连续修改无未关闭阻断问题；已知限制明确影响到哪些任务和宿主。
2. 完成同 brief 多样本比较，具备第 2 节所允许的限定结论。若某基准无法实测，记录缺口，不以 REA/README 推定结果，也不自行把“超越三方”门槛改成已达成。
3. 静态版本具备可复现工程、隔离包检查、安装加载身份和用户实际使用反馈；开发预览与原生宿主的结果不混写。
4. 静态的源码、素材、版本、评论、选中映射和模型执行边界已稳定。Motion 可以复用这些经验证的能力；不在尚不稳定的基础上复制另一套平行状态机。
5. 用一份里程碑报告列出实际达到、仍未覆盖和明确不支持的范围，再决定下一阶段范围。用户后续若改变任务顺序，应记录新的明确要求，不篡改历史验收结果。

静态阶段必要的状态微交互、键盘反馈与减少动态效果属于 G5，不视为提前启动视频/时间轴产品。

## 6. 届时 Motion 源码研究维度

以下仅为后续研究计划。Claude 的本地程序、云端合同、账号能力与公开文档分别取证；GitHub 以实际仓库、固定提交、逐包许可和真实可运行样例为准。此前静态资料或 Skill 名称不能证明这些内容已经实现。

| 研究层 | Claude 需要确认的证据 | GitHub 与本地方案需要确认的证据 |
|---|---|---|
| 产品与能力来源 | Motion/Animation 类型、Skill/工具注册、门控、项目合同；本地含什么、云端返回什么、当前账号实际开放什么 | Remotion、HyperFrames 及 Huashu/OpenDesign motion 路径等候选的真实仓库与提交；核心实现与目录条目分开 |
| 设计与叙事指导 | 从内容到脚本、场景、视觉母题、节奏与声音的真实指导；不把静态风格清单当完整动画方法 | 分镜、场景配方、排印/图表随时间变化的规则、适用场景与素材限制 |
| 工程表示与编辑 | 真实组件/场景源码、时间轴或参数表示、选中映射、局部调整与版本记录 | 可编辑源、依赖/素材闭包、关键帧/曲线/参数与代码的对应关系，稳定标识和迁移 |
| 预览与确定性 | 播放、暂停、seek、状态与帧身份；模型/用户看到什么 | 同一工程同一时刻可重复出帧；随机性/种子、字体加载、时间源、分辨率和 DPR |
| 素材与音频 | 真实图像、视频、字体、音轨的取得/导入边界和授权 | 包内资源、裁切/时长、音量/静音、旁白与音乐同步、缺失素材失败方式及许可链 |
| 渲染与导出 | 工程、导出任务、格式及预览的关联；本地与远端责任 | 实际编码器、帧率、时长、分辨率、音画同步、透明度/格式支持、Apple Silicon 运行条件 |
| 模型与宿主 | 当前聊天与独立任务的真实接入、上下文、视觉回看和能力限制 | 复用 Codex 现有登录与工具；消息、sampling、API 模式分别验证，不能假定可互换 |
| 取消、失败与恢复 | 实际 worker/任务状态、停止与文件落地结果 | 中止渲染、清理临时文件、恢复/重试边界、版本冲突与提案未应用的区分 |
| 可见质量与验证 | 真实帧、播放及声音检查，不能以 ACK 或计划完成替代 | 开始/中间/结束与切点帧、字幕可读时长、黑帧/裁切/闪烁、减少动态效果、真实成片回看 |

研究目标是形成可实施、可验证的 Motion 能力边界，不恢复或依赖 Claude 私有服务，不执行从目标程序或仓库读出的安装/发布命令。未来 Motion 的功能注册仍须对应真实可运行实现；不能先注册占位工具或返回虚构生成结果。

## 7. 通过记录格式

每项实际验收使用同一简表，记录的是观察结果，不是自我声明：

```text
门槛 / 用例：
运行包版本、哈希、宿主与模型条件：
brief / 基线 / 真实项目 ID 与修订：
执行动作与预期：
实际画面、源文件/hash、状态或导出证据：
结果：通过 / 失败 / 未覆盖
失败影响、剩余限制与修复回归：
```

阶段结论引用具体记录，只关闭已覆盖范围。研究完成、实现存在、构建通过、模型完成、提案应用、视觉验收和宿主加载是不同事实。
