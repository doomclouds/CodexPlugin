# Design 产品与架构

更新：2026-10-17。当前开发结构为 0.3；GitHub 已安装试用版为 0.3.0。用户明确要求开发阶段丢弃已淘汰方案，因此移除旧图层编辑器、场景文档、专用工具与生成分支，不提供旧格式迁移。下列新结构仍在集成验证，源码存在不代表全部验收通过。

## 产品目标与研发方法

在本地 Codex 完成需求、艺术判断、设计系统、可运行页面、连续修改与工程交付。主流程采用真实 HTML/React/TSX/CSS 源码；同一工程同时支持模型修改、属性窄范围修改和用户源码修改。

吸收 Claude Design、Huashu Design 与 OpenDesign 的具体优势，并从出版、导视、工业设计、建筑空间和数据叙事提出可检验假设。先记录所解决的问题、适用条件与机制，再用相同内容的作品和操作比较验证，保留失败与反例。研究见 [三方参考](open-design-references.md)、[研发原则](design-research-principles.md) 与 [规则样本](research-patterns.md)。方向目录数量不构成质量结论。

## 模型与宿主

默认当前聊天：Skill 引导当前模型读取源码、hash 和 revision 后调用工具，编辑器把选中源、评论与需求交给同一聊天。宿主缺消息能力时提供完整可复制内容，不伪称已发送。该路径不启动额外模型，也不要求 API Key。

独立任务仅在用户选择后，通过本机 Codex app-server、已有 ChatGPT 登录和实际模型目录执行。代码提案在私有副本中编译、渲染并交回同一模型审阅，完成后仍须按原 revision/hash 应用。代码已生成、已编译、已有截图、模型已审阅、用户主路径已实际操作分别记录。

合作伙伴登录并非本地插件必须实现的另一套认证。插件不读取或复制登录令牌，不增加私有云端接口，也不把全部 ChatGPT 产品模型视为 Codex 可用目录。原生 Codex、其他 ChatGPT 宿主和 CLI 分别验收。

## 真实项目与页面

当前结构采用 `schemaVersion: 2`。`pages` 的每页包含稳定 `id`、名称、真实源码 `entry` 和项目内 `route`；`defaultPageId` 选择默认页面，不保留旧的顶层 entry 别名。每页必须存在可编译入口。共享视口不绑定页面，专属视口通过 `pageId` 绑定；显式页面与专属视口冲突时拒绝。

文件集合包含文本与实际资源字节。工程修改同时校验项目 revision 和各文件 hash；未变文件不改写，多个变更原子保存。撤销、重做和恢复产生新的可审查 revision。版本、字节、文件数、路径与保存历史均有预算约束。

旧开发格式读取明确返回 `UNSUPPORTED_FORMAT`，不自动迁移或静默重写、删除文件。可用项目与不支持格式的诊断分列，不能让一份旧数据阻塞创建和使用新项目。这是失败诊断，不是旧编辑路径。

## 预览、定位与交互

WebAssembly 编译器只打包项目文件、实际导入组件与内置 React，不在后端执行项目脚本、安装依赖或运行包钩子。缺失依赖、越界路径与外链资源明确失败或报告。

页面在独立 sandbox iframe 内实际执行。允许本地脚本与本地表单事件；不开放 same-origin，CSP 禁止网络连接和网络表单提交。页面导航通过经过校验的项目内路由与 `design:navigate` 消息选择实际入口。宿主核对 frame、项目、修订及当前 pageId，再重建目标页面文档。不声称兼容任意第三方 router 或直接改写 location 的全部行为。

源码定位采用编译器 registry 与真实文件 hash。静态字面文字和可安全解析的内联样式可窄范围写回；动态表达式、复杂子树和运行时生成内容通过源码修改。稳定语义标记与评论在同一修订写入；失锚不能按旧 offset 猜绑。

无源码变化的面板操作与同修订轮询不应重启原型。源码重新编译或跳转页面会重建浏览器文档，临时 React 状态不能未经验证声称保留；持久源码、评论与版本是另一种状态。

## 组件、素材与工程交付

用户显式指定组件根目录、入口、CSS、类型和用法后，静态打包真实依赖及资源闭包。产物包含实际组件模块、样式、API 资料、来源 hash 和接入说明。打包成功仍需接入页面、编译、运行和视觉核对。

导出 HTML 保留可运行原型；多页通过包含所有实际编译页面的路由壳交付。源码 ZIP 分开保存原始文件、项目描述和可运行 HTML。PNG/PDF 直接渲染所选真实页面与视口。导入目录只读取并创建项目；导出目录遵守同步清单和外部 hash，冲突与部分写入必须实际报告，不覆盖无关文件。

发布包仅依赖包内 runtime、资源和 Skill。研究与实现记录放在仓库 docs，不能成为发布 Skill 的执行前置。所有直接和传递文件引用在脱离工程的隔离目录验证。

## 失败恢复与证据

独立任务总预算、取消和实际 worker 退出分别核对。生成超时后已编译的私有草稿应明确标为未验收 checkpoint；不能放进可应用 changes。继续审阅是用户显式操作的新受限任务，重新核对账户、项目 revision 与源 hash，不伪称恢复旧进程，也不以切模型或省略看图制造成功。该恢复流程正在集成验证。

当前 0.2 真实任务已有一次 900 秒超时：首版编译与双视口截图完成，模型看图未完成，未产生可应用提案。新恢复机制须针对这个真实失败改进并实测，协议替身通过不能替代推理。

静态质量门槛见 [验收与 Motion 入口](static-quality-gates.md)。目前未取得“整体已超越三方”的证据；在线协作、云端分享、Motion 独立时间线和视频渲染均未实现。按用户后续指令优先开展 Claude Motion 的 REA，并行完成静态作品、连续改稿及真实宿主验证；Motion 实现和完成声明仍按实际验收推进。
