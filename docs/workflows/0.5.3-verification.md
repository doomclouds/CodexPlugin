# Workflows 0.5.3 验证记录

## 指定节点重试

`workflow_resume` 新增可选 `retryFromTaskId`，节点过程弹窗提供“从此节点重试”。当前运行须停止或失败，版本与节点须匹配；保留前面有效结果，使所选节点及后续缓存失效，保留尝试历史与执行配置。后续已开始的非幂等命令在准备前拒绝重复，不扩大已有授权。失效标记先持久化，准备失败和重启后仍有效。

普通继续不猜测 `ok` 等任意业务字段。worker 可以正常返回未通过业务核验的结果；任务仍标为完成，工作流失败显示后续检查或结果判断错误。需要重新核验时，明确选择节点重试。

正式 SDK MCP、隔离完整包、签名桌面 CLI 与三个真实 `gpt-6-luna / max` worker 验证通过：前序读取固定标记，核验读取生成的 approval 文件。首次两个 worker 正常完成、业务验收失败；修改被忽略的验收输入后，普通恢复复用旧结果且没有新增 worker；重试 `task_2` 只重新派发核验，前序仍 cached，尝试数由 `[1,1]` 变为 `[1,2]`，最终完成。工具 ABI、原生命令、来源配置、删除与无残留均核对。测试脚本在仓库根目录，不进入插件包。

失效边界按调用位置计算，后面的节点不使前序缓存失效。受控异步等待回归对旧布尔实现作负向对照，验证新实现保留前序；此测试属于延迟 discovery 的防御性验证，现有常态消息调度未自然复现该竞态。

## 恢复检查点与 Git 缓存

快照检查点覆盖整个隔离目录，包括忽略的构建产物。哈希有文件、字节、层数限制，读取验证所有权与竞态，不追随外部链接。Git 元数据必须是独立自有目录，不接受外部 gitdir、common directory 或非空 alternates。

Git index 使用暂存记录及稳定语义标志，普通 `git status` 的 stat 缓存刷新不影响结果；真正暂存变更、assume-unchanged、skip-worktree、intent-to-add 均使缓存失效。intent-to-add 的位定义依据 [Git 官方实现](https://raw.githubusercontent.com/git/git/master/read-cache-ll.h)。只读 Git 缓存还包含 HEAD、分支、refs、本地配置与已初始化子模块。

隔离回归覆盖同内容时间变化、index 字节刷新、仅标志变化、真实暂存变更、忽略产物篡改、Git 元数据重定向、非 Git 项目及重启恢复。原项目文件和提交保持不变。

## 兼容与限制

已经派发过任务却没有检查点的旧快照须新建预览，不能追认旧验证。旧只读记录、库历史读取和删除、已有 Git 维护运行分别保留兼容路径。快照资源上限为单文件 512 MiB、总计 2 GiB、100000 个文件；超限明确失败，不跳过产物。

异步 pipeline 的结果完成顺序变化可能使更多缓存保守失效，现有输入指纹防止错取结果，非幂等命令仍禁止自动重发。外部副作用不能承诺只发生一次；工作流作者须按实际效果判断。首次签名 CLI 左分支语义结果不符尚未定位，原样复测通过也不抹除首轮失败；详见 [稳定性矩阵](stability-2026-10-15.md)。

最终 `npm run check` 通过：334 项运行时检查，333 通过、1 项 opt-in 真实沙箱检查按默认配置跳过；18 项可移植性检查通过。独立 MCP 包确认正式入口、21 工具、面板及资源别名。类型、构建、技能引用与发布路径校验通过。
