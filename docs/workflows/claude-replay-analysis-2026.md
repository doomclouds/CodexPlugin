## 已确认的静态事实

普通 Workflow 启动参数没有显式 `v2Run`，核心执行器保留可选的 v2 分支。world 初始化的两个调用位于 `runId` 扩展分支；该构建的扩展获取函数为空，在初始化前拒绝此分支。因此不能把 world 类存在等同于普通脚本实际采用它，也不能仅由可选分支推断整个运行时选择。

存储分为两层：

- **每次运行的 agent journal**：记录 started、result、failed。缓存键由前一个键、prompt 与规范化选项组成哈希链，选项包含输出 schema、模型、effort、隔离、代理类型与工具限制；对象键排序，展示标签不决定缓存身份。started 没有结果且未记为失败时，可以重新执行该任务并继续保留后续匹配的结果。结果缺失与明确失败是不同状态。
- **world journal**：静态实现记录 put、settled、retracted，并按连续地址前缀恢复。恢复把 pending 记为 lost，把 live 订阅撤回，不保存 VM、规则闭包或活跃工作。旧 world run 的继续操作会拒绝，允许读取事实或重新启动。其当前门控未启用，不能称为已运行验证。

world 写入串行排队；追加失败后脱离写入，后续只留内存。读取识别损坏行与不完整尾行，未完整恢复时不附加新的写者。agent journal 的写入失败会记录警告；这也不能提供副作用恰好执行一次的保证。

v2 规则回调采用独立、不沿主脚本哈希链的 memo，避免事件到达顺序误用主链缓存。撤回按子作用域传播取消；未等待的子工作流可被切断。任务注册层保留暂停／停止状态，并拒绝旧运行尚未退出时再次恢复。

## 推断与未知

哈希链可以发现顺序、prompt 和执行选项变化，但不能证明外部副作用没有发生。进程可能在写文件、提交远端请求或更新配置后、保存完成记录前退出；自动重试必须结合可验证的后置条件和幂等规则。

外部 runEngine 是否动态注入 v2、其他构建是否启用 world 扩展、全部权限默认值及远端 storage 的原子性，不由本次所选模块确定。文档中的恢复说明不能直接扩大成任意任务或费用的硬保证。

## 对本插件的质量要求

1. 任务缓存纳入真实执行范围，恢复核对固定提交、源文件与构建产物，不能只比较 prompt。
2. 将未开始、确定失败、中断、结果已保存以及副作用结果不确定区分；维护操作先核对后置状态，不能无条件重复执行。
3. 任务发起与结束具有可验证身份；存储损坏或保存失败明确暴露，不继续声称可恢复成功。
4. 停止等待真实进程退出，再开放恢复；进程内取消、磁盘状态和宿主控件分别验证。
5. 配置激活持久化单服务器前像和事务状态，使用版本 CAS；崩溃后识别已经达到的目标并保留原前像。
6. Git 快进和配置激活是两个可分别失败的阶段。部分完成须明确显示，重试只处理尚未完成的阶段。
7. 权限由预览声明与实际沙箱核对共同决定；用户请求、多样任务和已配置工具白名单不能被某个具体工程的维护脚本替代。

这些是实现质量的检查项，不表示本插件已经实现 Claude 的 world API、所有 agent 选项或完整兼容。
