# Workflows 0.3 维护层验证

日期：2026-10-14。范围为通用独立 Git checkout、提交与产物校验、原仓库快进和单 MCP 服务器激活，不依赖某个工程的固定目录或构建脚本。

## 实际检查

`maintenance.test.ts` 的 13 项检查通过。Git 测试在可删除的本地仓库与本地 bare remote 中创建真实历史并执行实际命令；没有向公共远端推送。

| 检查 | 结果 |
| --- | --- |
| 独立 checkout | 保留完整提交历史、remote URL、分支和 upstream；Git 元数据不共享，也不借用原仓库的 alternates |
| Git hooks 与模板 | 准备时显式使用空模板与空 hooks，覆盖宿主 global hooks；不导入原仓库的 hooks 配置，原配置保持不变；检查点只保存本地 Git 配置的哈希 |
| 预检与恢复 | 脏原仓库拒绝准备；原 HEAD 或分支变化拒绝复用 |
| 最终审查 | 固定目标提交，记录源码差异和全部忽略产物的哈希 |
| 变化与路径边界 | 构建产物或源码变化使审查／检查点失效；拒绝外部链接和被替换的父目录；普通文件用不跟随最终链接的 fd 并核对文件身份 |
| 原仓库应用 | 实际快进到已验证目标；不从变化的远端重新取目标，不把忽略产物复制回原仓库 |
| 冲突与分叉 | 原基线变化或目标不是快进后代时拒绝应用 |
| 配置范围 | 只修改声明的 stdio MCP server 的 command／args，保留环境、超时、其他 server 与配置注释 |
| 配置并发 | 真实版本 CAS 拒绝并发变更，不覆盖另一处编辑 |
| 配置回退 | 写入后注入校验失败，实际回退该 server 并重新读取确认恢复 |
| 中断恢复 | 前像 journal 尚为 prepared、配置已达到目标时，不再次写入，不把目标配置误当成旧前像 |
| 部分完成 | 原仓库已经快进、配置激活失败时明确保留两者状态；重试只完成激活，不再次 pull |

其中 5 项启动了真实 Codex app-server，在子进程自己的临时 Codex 配置目录操作。它们没有调用模型，没有修改真实用户配置，也没有重载桌面连接。备份和单服务器事务 journal 保存在私有运行目录，文件权限为 `0600`。

## 边界

激活成功返回 `pending_restart`，仅说明磁盘配置已经修改并校验；不证明当前聊天的 MCP 连接加载了新命令。实际连接身份必须在宿主重载后另行核对，不能把新配置与旧进程混为成功。

工作区采用完整、独立的 Git checkout，不是共享原仓库元数据的 linked worktree。应用不自动提交工作区的脏源码，不自动合并分叉，不自动部署其他文件目录。产物保留在已验证工作区，激活参数通过运行时工作区变量定位。

配置修改与 Git 快进不是跨进程的单一原子事务。配置失败可以留下已推进的源仓库，这种状态必须明确显示；配置 journal 的条件回退不能覆盖随后出现的外部修改。构建、拉取和外部工具的副作用也不具备任意“恰好一次”保证。

本记录不代替完整工作流的模型调用、网络沙箱、工具权限或原生宿主按钮验证。测试操作只使用拥有的临时数据，原配置内容、凭据、机器目录和原始诊断日志未写入本文。
