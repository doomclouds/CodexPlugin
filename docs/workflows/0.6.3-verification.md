# Workflows 0.6.3 验证记录

## 本次问题与证据边界

REA 的本地运行已完成预检，更新节点在等待代理反馈时被手动停止；日志没有记录该节点执行原生命令。恢复在准备阶段被旧本地检查点拒绝，没有启动新的更新、安装或构建任务。

实际读取核对了 3,846 个基线文件的内容与权限，HEAD 与预检结果相同。停止之后未发现非 Git 文件或目录的修改时间、状态变更时间变化。发现 Codex 在停止后写入了 `refs/codex/turn-diffs/checkpoints/` 内部引用，指向与 HEAD 相同的树。

旧算法包含所有 Git 引用，因此这类宿主记账会造成误报，已在独立项目复现。但这条历史记录仅保存总摘要：移除新增引用、移除所有同类引用，以及核对旧版发布运行包，均未复原保存的总摘要。因此不能认定内部引用是该历史记录的唯一差异，也不能以当前状态覆盖旧摘要后声称安全恢复。

保留旧运行，使用工作流库的最新定义创建独立预览，尚未启动。没有自动继续 REA 拉取、构建或配置更新，也未清空历史或撤销原项目文件。

## 修复

本地 `local-v2` 检查点只排除精确命名空间 `refs/codex/turn-diffs/checkpoints/`，包含初始化子模块中的同类记账。源码、忽略产物、文件权限、HEAD、分支、索引、普通分支／远端／标签引用、其他 Codex 引用及本地 Git 配置仍参与核对；原只读及隔离执行的默认摘要兼容语义保持。

文件树只完整扫描一次，同时生成新版摘要和有界旧版候选。内部引用在扫描期间变化时不阻断新版；全部 Git 引用前后不稳定时不提供旧版完整候选。旧记录仅在完整旧摘要精确匹配，或仅排除内部引用后重构的完整旧摘要精确匹配时迁移；不能还原的旧记录要求新预览，没有时间戳推测、任意引用子集接受或强制重置。

新增文件与 Git 两个分项摘要，仅用于后续报错定位，不作为放宽缓存接受的依据；工作区目录身份、基线、项目串行锁及真实改动检查保留。

本地检查点拒绝恢复后，面板主按钮改为“重新检查”，按原脚本、参数、权限及限制创建独立草稿，不自动启动。旧来源版本已更新时保留版本保护，提示从库选择最新定义。旧运行及已有文件保留；创建草稿后仍需明确点击“启动”。
