# Workflows 0.5.2 验证记录

## REA 前置核验错误

现存 REA 运行停在只读核验：worker 调用 `collaboration.spawn_agent`，宿主返回 `failed to load model context for thread; invalid thread-store request: no rollout found`。worker 因任务要求而停止，输出未通过核验的结构化结果；脚本断言使运行失败，后续拉取、安装、构建、应用均未执行。

在签名桌面 CLI 0.162.0-alpha.17.2、`gpt-6-luna / max` 上精确复现。该 CLI 使用 `agents.enabled` 控制 code-mode 的委派工具，原有 `features.multi_agent=false` 不足以移除它；内存线程没有可继承的持久 rollout。

修补在进程和线程配置两处设置 `agents.enabled=false`，保持内存线程。脚本的 `agent`、`parallel` 和 `pipeline` 负责受预算控制的并行；原生命令、文件、补丁和已授权 MCP 保留，不禁用 code-mode host、不创建永久 worker 聊天。真实修后读取与 `apply_patch`、Node 断言均成功，委派工具已从实际工具目录消失。

正常完成的 worker 可返回未通过业务验收的结果；运行时不能猜测任意业务字段的含义。旧运行继续时仍可能复用此结果，显式选择节点重试与其他缓存一致性修补列入下一补丁。

## 另外两项修补

- 内置库的裸 ID、版本零与持久化来源校验不兼容。新记录规范为 `builtin:<id>`；兼容实际已知的旧裸 ID，保存定义仍要求正版本。内置历史记录保留其脚本，即使以后目录移除该定义也可读取和删除。真实 MCP 测试覆盖库读取、预览、更新、启动、列表、重新打开和删除。
- `parallel`、`pipeline` 的长错误超过日志传输限制，使本应返回 `null` 的失败变成顶层失败。内部诊断截断至既有 4096 字符限制，保持错误处理契约；长错误回归通过。
