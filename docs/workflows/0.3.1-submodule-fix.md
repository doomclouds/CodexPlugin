# Workflows 0.3.1：REA 工作区准备修复

## 问题与修复

REA 的五个 `third_party/` 路径是 Git 子模块，索引模式为 `160000`，当前均未初始化。旧版本计算项目摘要时把 gitlink 当作普通文件读取，在启动 worker 前报 `Unsupported workspace entry: third_party/binwalk`。

0.3.1 按提交和初始化状态记录子模块。Git 模式只从本地复制已经初始化的模块及嵌套模块，每份副本拥有隔离区内的 Git 元数据；未初始化模块保持原状态，不自动下载。审查、检查点和恢复包含子模块状态及构建产物。文件快照写入遇到子模块会提示创建 Git 模式预览。

应用时只同步原仓库已初始化的模块，使用持久化日志记录进度；中途失败明确返回部分应用，重试核对原状态和已完成状态，拒绝覆盖后续用户修改或忽略文件。宿主准备阶段禁用隐式递归传输、内容过滤命令与文件监视命令。

同时修正实际计划里的两个后续问题：允许绝对路径的 Node、npm CLI 和只读脚本参数，由真实操作系统沙箱限制写入；每次命令的 npm/XDG 缓存及临时目录默认放入隔离工作区并在结束后清理。精确 argv、HOME、PATH 和全局配置保持原值。

面板按实际错误分类提示，只有版本冲突建议刷新；部分应用分别说明尚未完成的子模块或激活步骤。
