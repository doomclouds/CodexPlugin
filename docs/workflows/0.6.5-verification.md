## 插件修复

MCP 完成事件保留按调用 ID 去重的失败诊断，覆盖协议 `error`、透传 `isError`、有限文本和明确的结构化错误路径。记录安全验证后的服务和工具名，不转存入参、成功结果、图片、资源、任意结构对象或深层数据。

诊断在取样、脱敏后再次按 UTF-8 字节限制；每次最多 8 KiB，每 worker 最多 100 条及 64 KiB，总量不足时仅提示已省略。覆盖引号与换行凭据、URL 认证和敏感查询、截断 JSON、嵌入 args/prompt，避免诊断成为输入或私密信息转储。单次工具失败不由 Adapter 自动升级为整个 worker 失败，脚本仍可按明确逻辑恢复；实际失败活动保持可见。

worker 包装将整体目标、声明阶段和当前阶段作为单行 JSON 背景；原任务文本保持不变。说明当前节点只完成自己的委派检查，不因全流程目标或可用工具而提前完成后续连接、部署和验收。代码修改仍可做相关测试。命令或工具失败时要求在既定报告形状内保留真实原因，区分未执行与已执行失败，不只返回 isError，也不重试被拒绝的动作或换接口绕过审批。这是行为指引，不保证模型绝不偏离。

阶段在 dispatch 开始时捕获，避免模型环境读取或排队期间全局阶段已经推进，导致前一个任务错绑到后续阶段。未按任意 output.status 字段猜测业务成功或失败，也未把 finally 清理后的最终 throw 强行归因给其他节点。

## 审批边界

worker 保持非交互 `approvalPolicy: never`，工具白名单和用户原生审批策略分别生效。没有自动改为 approve、伪造只读注解、开放所有 MCP 或直接连接 REA 绕开审批。当前有效配置没有为 `rea/binary_session` 设置预批准。

如果用户明确选择预批准，可在其 Codex 用户配置中仅设置以下工具，其他工具、沙箱与过滤保持原样；本轮仅准备建议，尚未应用：

```toml
[mcp_servers.rea.tools.binary_session]
approval_mode = "approve"
```

这是一项持续的逐工具信任设置，需要用户明确同意，不能从工作流白名单推导。依据：[Codex 逐工具审批配置](https://learn.chatgpt.com/docs/config-file/config-reference) 与 [App Server 审批接口](https://learn.chatgpt.com/docs/app-server)。当前集成仍不支持现场交互审批，不能声称已实现审批转发。
