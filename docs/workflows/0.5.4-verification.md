# Workflows 0.5.4 验证记录

模型目录缓存原本对完整有效配置的原始 JSON 计算键。Codex 在不同进程中返回的对象字段顺序可能不同，配置值相同也会产生不同摘要，导致目录重复获取。

仅对缓存键的对象字段递归排序，保留全部真实值及数组顺序。每次仍从新会话读取真实配置，用新配置解析默认值、权限及 MCP 范围；缓存只包含模型目录，按 cwd 和完整配置隔离，不复用 worker、授权或运行时状态。

新增四项协议回归通过：三次同目录配置读取只有字段顺序变化时仅一次 `model/list`；command、环境值及 argv 顺序实际变化时分别失效，之后的相同配置可以复用。原目录隔离、过期、关闭和配置读取检查保留。

真实签名桌面 CLI 实证：两次新会话、同目录，`config/read` 两次、`model/list` 一次；原始配置摘要不同，规范化摘要一致，两个模型目录完全一致。未发送模型 turn，用户配置摘要不变，诊断夹具已清理。

这项修补减少无谓目录请求。本机一次目录读取约几十毫秒，不能用它解释分钟级启动或构建时间。任务执行和构建耗时仍以实际阶段及节点过程判断。

完整稳定性验证、保留的语义偏差及范围说明见 [今晚矩阵](stability-2026-10-15.md)；节点重试与检查点见 [0.5.3 验证](0.5.3-verification.md)。

`npm run check` 通过：338 项运行时检查，337 通过、1 项默认跳过；18 项可移植性检查通过。构建、类型检查、独立 MCP 包、技能引用和发布路径检查通过。
