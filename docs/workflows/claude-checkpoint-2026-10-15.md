# Claude Code checkpoint 与 Workflows 节点恢复研究

研究日期：2026-10-15。本文仅为工程研究，不随插件发布，不是任何 Skill 的执行依赖。本次通过 REA MCP 对实际发行模块做静态分析，并逐字节核对原发行文件；没有运行 Claude、其 bootstrap 或提取出的应用代码。

## 结论与实现边界

Claude Code 的工作流恢复、文件回退和对话恢复是三种机制：

| 机制 | 保存的对象 | 恢复动作 | 不提供的保证 |
| --- | --- | --- | --- |
| Workflow agent journal | 调用身份、started/result/failed、代理 ID、完整返回值 | 重新运行脚本；输入和前序链匹配时返回已保存结果，其余调用重新派发 | 不恢复 JS VM、进程或任意外部副作用 |
| File history checkpoint | 消息 ID、受跟踪文件的备份、版本与路径身份 | 显式 rewind 时恢复备份或删除原先不存在的受跟踪文件 | 不涵盖全部 Bash/MCP/远端操作；不是项目或系统级事务 |
| Conversation resume | 历史消息及关联的 file-history 索引等状态 | 恢复对话和快照索引；跨会话迁移备份 | 单纯 resume 不自动 rewind 文件 |

Workflows 应先完善自己的节点结果恢复契约、恢复前检查和可见恢复计划。文件回退需要单独的能力、预览和冲突处理，不能让“从此节点继续”隐含撤销本地代码或远端操作。Claude 的存在性证据也不等于可以直接照搬其内部实现或宣称完整兼容。

## 已确认：Workflow 恢复是确定性脚本重放和结果复用

`Do` 将 journal 的 `result` 收集为按 key 索引的结果，将 `started` 收集为尝试列表，将 `failed` 收集为独立集合。`sn` 读写逐行 journal，支持本地文件和 storage V5；`Ko` 在本地追加后可向会话存储镜像。

`No` 的 key 是带版本前缀的 SHA-256，内容依次为：前一个 key、分隔符、prompt、分隔符和规范化的执行选项。`Hr` 选取 schema、model、effort、isolation、agentType、disallowedTools、bashCommandClamp，忽略函数值，对对象键排序；工具限制还会预先去重、排序。label 和 phase 展示信息不会单独决定该缓存身份。

`ir` 从空链开始依次为 agent 调用分配 key，并在真实派发前查询已保存结果。命中后返回结果的 VM 安全克隆，同时发出 `cached` 完成进度；不会重新调用模型来“重现”同一输出。恢复后分支和循环依赖已返回结果重新走脚本控制流，而非恢复一个被冻结的 VM。

缓存缺失有两种不同处理：

- 有 started、无 result、没有显式 failed，且之前链还未失效：该调用重新派发，后续匹配 key 的已保存结果仍可能复用。
- 没有对应 started、有显式 failed，或此前已经失配：令当前重放链失效，后续不再读取旧结果。

started 记录中的历史代理身份未在这一分支被直接用来复活旧进程；所见代码进入新的派发路径。不能把“重新派发中断节点”称为“恢复原 worker 的内存”。模型会话恢复是另一层可独立实现的能力。

确定性还有运行约束：VM 禁用依赖当前时刻的 `Date` 用法和 `Math.random()`；脚本时间或采样身份应由 args/明确索引传入。`parallel` 使用函数数组及 `Promise.allSettled`，保留槽位结果；pipeline 的每条 item 路径按阶段执行。异步完成顺序不等于可靠调用身份，复杂并行/循环仍须有稳定的逻辑身份与输入核验。

后台 adopt 的 `QGo` 在读取并编译脚本前要求保存的 `scriptSha256`，不匹配时拒绝接管并要求通过正常 Workflow 入口重新审批。该事实不应扩大为“所有调用路径、全部外部输入都自动包含在同一 hash 中”。

## 已确认：journal 不等于副作用事务

started 写入位于代理身份取得后的回调，异步追加失败会记录警告。正常非空 result 的追加会等待，但失败同样被 catch 为警告；failed 追加也可能失败。取消状态不写普通 failed。历史日志的解析失败行被跳过，remote restore 另外使用 restoring/restored 标记识别不完整的恢复。

由此不能推出以下保证：工具执行前 started 已经可靠落盘、工具结果必然保存成功、磁盘完成标记与远端写入原子提交，或某个动作恰好执行一次。尤其存在“写代码/发布/更新配置已经发生，但 result 尚未落盘时进程退出”的空窗。

Workflows 应避免复制宽松写盘语义：需要把 checkpoint 可恢复性作为宿主独立状态，只有结果与相应执行证据都保存成功才公布可复用的完成边界；持久化失败应显式报告恢复能力降级。中断且有潜在副作用的节点应先检查后置状态，再决定复用或重做。

## 已确认：文件 checkpoint 与 rewind 的职责

`Fet` 为工具编辑建立初始文件备份或“原文件不存在”的标记。文件写入、字符串编辑、notebook 编辑等可见调用路径在实际写入前调用它；这不证明所有 Bash 或第三方 MCP 写入都被覆盖。

`Tke` 在消息边界为 trackedFiles 生成下一版本备份；内容无变化可沿用已有备份。快照包含 messageId、trackedFileBackups、timestamp 与可选 preCheckpoint。文件记录包含备份文件名或 null、版本、时间及 realParentDir。`rhe` 更新内存索引并追加快照/delta；历史条数受上限控制，淘汰时回收不再引用的合适备份。

`XC`/SDK rewind 是独立、显式操作，先检查功能启用和目标快照存在；dry-run 只计算文件列表及增删统计。真正 `Z6t → kVr → RVr` 才修改受跟踪文件。原先不存在的受跟踪文件可以删除；已存在文件从备份恢复。缺失备份、特殊文件、符号/硬链接或父目录身份变化均有拒绝或失败分支；打开后还会校验 fd/path 身份，避免仅靠第一次路径检查写错目标。

所有不同文件的恢复不是一个跨文件原子事务。源码分别统计 changed、failed、skippedLinks；全部差异文件失败会抛出专门错误，部分成功也保留失败信息。备份创建失败可被记录后继续原操作，因此不能声称每次工具编辑必有可用的前像，更不能声称 rewind 总能恢复所有改动。

## 已确认：会话恢复保留索引，不自动恢复文件

`Ngt` 取得会话中的 fileHistorySnapshots 后调用 `eVt`，把快照和 trackedFiles 重建到应用状态；这条路径本身不调用 Z6t。跨 session 恢复时，`kkn` 迁移备份：优先 hard link，失败可复制到临时文件后 rename；仅对所需备份全部成功迁移的快照写入恢复记录。缺失、复制不完整、重命名失败明确记录，不能因恢复了对话消息就认定全部备份可用。

SDK 单独暴露 rewindFiles 请求，参数包含 user message ID 和 dryRun。所见 SDK 还明确拒绝 file checkpointing 与某个 sessionStore 组合，因为该存储不镜像备份正文，恢复后 rewind 会失败。这进一步证明 transcript 与文件备份正文不能混作一个完整快照。

## 已确认但有门控限制：world journal

`rt` 从 put/settled/retracted 记录重建 world，遇到地址缺口只恢复连续前缀；pending 转为失败的 lost 状态，live subscription 撤回，不恢复闭包或活跃 work。`kr` 只在未跳过行、地址完整等条件全部满足时附加新 writer；不完整时保持内存状态并报告不能完整附加。旧运行被标为 lost 后不假装继续原来活跃计算。

这些代码位于已有研究确认的可选 v2/world 分支。该发行构建的扩展获取函数为空，普通 Workflow 路径没有证明启用此门控，因此只可作为静态设计参考，不能称为该产品本次实测的默认执行路径。

## 对 Workflows 的可落地要求

以下是基于证据提出的设计建议，不是 Claude 已公开的兼容 API，也不表示 Workflows 已经全部实现。

1. **提供恢复前只读计划。** 明确当前可复用的节点、重跑起点、后续失效范围、workspace/脚本/执行范围核验结果和阻塞原因。用户日志只显示简短结论；开发日志保存各项比对依据。计划不启动 worker、不刷新 checkpoint、不改磁盘文件。
2. **把完成结果与 checkpoint 绑定。** 保存 run/task/attempt、输入签名、结果摘要、workspace 状态、完成时间及格式版本；成功落盘之后才能作为可复用边界。恢复不能用最后的 UI 状态或模型文本替代真实持久化结果。
3. **从节点继续保留有效前缀。** 脚本重放时只返回已经核验的缓存结果，从选定节点及后续按既定流程重新派发。显式重跑旧成功节点应把它及后续结果失效，不能让旧输出悄悄复用。循环同名节点须以真实调用/迭代身份区别，不能按 phase/label 匹配。
4. **区分任务中断与脚本中断。** 进程退出、取消、明确失败、成功结果已保存、结果已产生但保存失败、有可能发生副作用，分别展示。脚本 finally 中的清理、错误重抛不能覆盖原始失败来源或把半完成工作包装成成功。
5. **副作用需要核对，而非无条件重做。** local 代码、Git、构建产物、宿主配置及远端状态分别核验。具备事务记录的维护操作可识别已达到后置条件；普通模型工具调用未知时应明确提示需核对。节点恢复不承诺任意外部动作回滚或 Exactly-once。
6. **保持运行独占与审批范围。** 旧 worker 真正退出之后才恢复；恢复计划与执行用 revision/CAS 及所有权再次校验，不能把旧预览当永久授权。工具、文件、网络和审批拒绝边界不因 checkpoint 放宽。
7. **不把文件 rewind 混入本次 resume。** 若后续开发文件回退，单独提供文件差异预览、备份覆盖说明、用户新改动冲突保护、链接/目录身份检查和部分失败报告。未实现前必须说明只复用结果、不撤销已生效改动。

验收至少覆盖：节点完成后宿主重启仍复用结果；失败节点纠错后继续；分支/循环路径重放；并行节点完成顺序变化；恢复前脚本/输入/权限或 workspace 变化；选定节点强制重跑；停止时 worker 尚未退出；中断后存在本地或外部副作用；保存结果失败与损坏记录；恢复计划期间状态改变。真实 worker 的恢复应另做验证，静态研究和替身测试都不能替代。
