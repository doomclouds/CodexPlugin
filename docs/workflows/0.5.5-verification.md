# Workflows 0.5.5 验证记录

## 项目入口

面板只注册 thread 入口，移除主窗口左侧栏 global 入口。宿主聊天必须有可信项目归属，面板才能读取该项目运行、参数或执行设置。所属项目固定；跨项目复用时，在目标项目聊天中从库创建独立运行。无项目聊天显示明确引导并禁用操作，不以工作流输入中的路径反推聊天归属。

显式、经用户授权的模型 MCP 工具仍可指定 projectPath，不受面板入口限制。旧宿主菜单可能缓存旧工具元数据；安装新包与当前 App 重新加载分别验证。

## 失败与停止

脚本后置断言失败时，已经完成的 worker 保持完成；失败阶段显示“结果检查失败”。主按钮打开失败原因，不会在普通继续时无限复用相同业务失败结果。需要重新执行时，从节点明确重试，保留前序有效缓存和非幂等操作的保护。

准备失败、脚本失败、检查点失败分别记录来源。旧记录仅根据本次开始后的受声明阶段日志判断失败位置，不解析任意业务字段。顶部错误简短展示，完整错误折叠在节点弹窗，输出转义、脱敏并限长。

停止记录用户请求、面板关闭、连接过期、服务关闭和原执行进程退出的原因。正常停止不再把通用 Abort 当成运行失败；服务关闭后拒绝新的执行派发。readonly worker 得到避免 shell here-doc / here-string 临时文件的通用指导，权限保持只读。终端完成事件在缺少流式输出时补录实际 aggregate 输出及失败状态，已有流式内容不重复。

## REA 真实排查

旧运行的普通恢复复用了已完成的失败业务结果；显式重试后确实启动了新 worker。旧 Sol/ultra 尝试由本次排查主动停止，随后用户再次恢复的尝试报告只读 shell here-doc 临时文件写入被拒绝。改用 Luna/max 的新尝试约 46 秒后返回命令构造错误，不能归因于 rollout 丢失。

为该维护计划新增确定性、只读的 inspect-facts argv 操作，代替三处模型拼接 shell 采集事实；原业务断言、维护命令和权限范围保留。新运行的前置核验、fetch 和拉取后核验成功，fast-forward 因隔离副本内受保护 .agents 路径不可写而停止，未派发安装和构建；此条是新发现的实际限制，不能将其记为成功。
