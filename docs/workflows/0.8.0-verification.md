# Workflows 0.8.0 节点检查点设计与验证

日期：2026-10-15，Asia/Shanghai。本文为开发验证记录，不随插件发布，也不是 Skill 的执行依赖。

## 问题与设计

用户需要工作流在停止或执行器退出后保留已完成节点，并从可信边界继续。检查点必须说明哪些结果能够复用、哪些节点需要重新执行、当前文件是否仍与已保存进度一致；不能仅把界面显示“完成”或 run.json 中存在 output 当作可靠完成边界。

本版将节点进度恢复与文件回退分开：恢复重新执行工作流脚本，以经过核验的节点结果重建原有分支和循环；当前项目文件原样保留。本版没有文件 rewind，不撤销 local 模式已经生效的改动，不回滚 Git、宿主配置、MCP 或远端副作用，不承诺任意外部动作的 Exactly-once。停止后执行过的写入可能有部分效果，必须按已保存证据和真实后置状态核对。

实现围绕三个边界：

1. **先持久化，再承认可复用。** 独立、不可变的 checkpoint manifest 保存格式版本、顺序、前驱引用、计划身份、工作区指纹和 task/attempt/输入/输出身份。先将 manifest 落盘，再通过 durable run.json 更新原子提交指针和匹配结果。未被已提交链引用的独立文件不作为完成证明。
2. **没有实际 worker 时捕获稳定状态。** StableCheckpointGate 不改变原有读取并发和写入池；最后一个实际 worker 完成并结算 attempt 后才执行 capture，期间新 worker 等待。非最后离开的 worker 不等待其他 worker，避免并行调用相互阻塞。保存失败会阻止后续 worker，不能继续生成新副作用后声称旧检查点仍覆盖当前状态。
3. **恢复预览只读，确认时再次核对。** 展示复用、重跑与失效节点、当前 checkpoint 及阻塞原因，明确保留文件和不撤销外部效果。确认恢复携带预览 fingerprint，并在执行前重新检查 revision、计划、模型/授权范围、文件状态及节点结果身份；过期或阻塞预览不能启动 worker。旧执行器尚未退出时不能恢复。

持久化保证以平台能力为界：POSIX 上同步文件、包含目录及运行目录，先写不可变 manifest，再同步更新 run 指针；Windows 同步文件内容，rename 的断电持久性由操作系统管理，不声称等价的父目录 fsync。进程 SIGKILL 测试不等于真实断电测试。

旧记录按已有证据保守迁移。旧 local 指纹只有精确核验成功才能转为新格式；旧 Git 指纹无法匹配增强后的语义范围时需要新预览。旧只读记录缺少节点 manifest 时全部重新读取。外部编辑、计划修改和无法核验的历史结果不会通过刷新摘要得到新的认可。

同一计划恢复或指定节点重试可保留有效前缀；显式修改脚本、输入、模型或执行范围后重新开始时，全部旧观察重新核对，防止异步发现顺序让读取抢先复用旧写入前的结论。两者不混用。

本次复审实际复现并修复了：旧计划中的写入变更与异步读取发现竞态、恢复校验后到提交前的文件漂移、旧版迁移重复采样造成的错误认可，以及子模块分支/ref/index flags 漏检。对应回归使用真实临时项目和文件/Git 操作；worker 为测试适配器，不能与下文真实模型验证混称。

## 确定性检查与真实进程崩溃

`tests/checkpoint-gate.test.ts` 的 13 项检查已通过，覆盖并行 worker 独立离开、最后一个 worker 等待稳定 capture、capture 中进入下一波、失败后关闭入口、取消等待及监听清理、重复 release、连续 wave、同步异常和 callback 重入。

`tests/checkpoint-crash.test.ts` 与 `tests/fixtures/checkpoint-owner.mjs` 使用真实 Node 子进程、WorkflowEngine、RunStore、文件 IO、不可变 manifest 和真实 SIGKILL。WorkerAdapter 是测试夹具，没有调用模型，也没有杀 Codex CLI。父进程仅终止自己创建的临时 owner，等待 close 后按真实过期锁恢复。

| 场景 | 已验证的边界 |
| --- | --- |
| task1 写入完成、稳定 checkpoint 已提交，task2 刚进入时 SIGKILL | 新 engine 只恢复状态，不自动派发；只读预览确认有效前缀；显式恢复只执行 task2，task1 写入次数、结果和原 attempt 保持不变 |
| task2 已写部分源文件后 SIGKILL | 预览被 workspace_changed 阻止；确认不能派发新 worker，部分源文件与先前结果保留，不回滚也不静默刷新指纹 |
| manifest 已落盘，但提交新 run.json 指针前 SIGKILL | 新 manifest 确实存在，但不进入已提交链；历史列表和读取只承认旧 pointer，不扫描孤立文件冒充成功 |
| 上述未提交结果没有改变项目文件 | 额外暴露并修复了仅凭 workspace 相同就复用孤立结果的问题；恢复还必须核对已提交 manifest 是否覆盖准确 task/attempt/输入与输出。写入结果未提交时阻止盲目重放，读取结果可按恢复计划重新核对 |

前三场首次执行 3/3 通过，约 17.7 秒；第四场先实际复现失败，修复后回归通过。最终整仓检查中四场全部通过。

本组检查证明的是插件 owner 崩溃后的磁盘恢复边界；不证明任意正在执行的远端动作可撤销，也不证明原生模型线程能够恢复其内存。

## 真实 gpt-6-luna/max 节点恢复

新增 `scripts/checkpoint-real-smoke.ts`，仅显式传入 `--real-workers` 才运行，并要求从 `CODEX_CLI_PATH` 获取原生执行文件。源码不固化开发者机器路径。未传开关时，在创建临时目录或调用模型前退出。

本次真实执行通过，约 40.9 秒，范围是临时非 Git 的 local 项目，两个 worker 都使用 `gpt-6-luna`、思考深度 `max`、无网络、无外部 MCP、审批模式 `never`：

1. task1 原生 worker 通过真实 native command 独占创建随机标记文件，并读取实际文件返回数据；schema 与 accept 均通过。
2. task2 第一次 dispatch 由外层装饰器挂起，明确位于调用原生 adapter 之前；随后显式 stop。此时 task1 已完成、task2 为 interrupted，attempt 数为 `[1, 1]`，完成结果与稳定检查点保留。
3. 关闭原 engine 和 adapter 后，使用相同私有 RunStore 新建 engine。重开和恢复预览均未调用模型，预览没有修改保存记录；计划复用 task1、重跑 task2。
4. 携带 preview fingerprint 显式确认恢复。task1 为 cached，原 attempt 全部元数据不变；task2 使用新的真实 native 只读 worker 读取标记并验收通过。最终 attempt 数为 `[1, 2]`，真实 native 调用总数为 2，其中 task1 仍只有 1 次。
5. 最终 execution 为 completed，形成 7 个已提交 checkpoint，包含 initial/node/final/recovery；标记和原 notes 内容均未回滚，项目没有额外文件。

两次真实调用分别是 `task_1_attempt_1` 和 `task_2_attempt_2`，都记录了 `native:commandExecution`、真实 thread/turn 和校验后的模型设置。第二次只读提示不包含随机标记值，必须读取真实文件取得它。装饰器透传 executionEnvironment、command 和 close，没有以伪造模型目录或模拟输出代替真实 worker。

这场 stop → close → reopen → preview → confirm 是真实模型参与的持久化恢复测试；**task2 第一次停在 native 派发前，不能称为杀掉真实 native worker 后恢复**。真实 SIGKILL 的四种磁盘边界由前一组独立进程测试证明，两个证据范围分别保留。

成功运行的脚本 SHA-256 为 `5903c26804791db855847793b79490dc4974e743e11bebb3a486f5e832ec1ccb`。使用私有临时 Codex home 复用已有登录，用户配置原始字节摘要前后一致；没有修改全局审批或 REA 配置。原生执行器关闭后清理了全部测试目录和临时凭据，最终成功日志在清理完成后才输出。没有操作 REA 项目或已有工作流数据。

冻结 0.8.0 产品代码后再次通过同一真实验证，耗时约 36.5 秒：仍为 2 次 `gpt-6-luna/max` 原生工具执行、7 个已提交检查点、首节点单次写入并复用、attempt 数 `[1,1] → [1,2]`，用户配置不变且临时凭据清理完成。此轮同样没有宣称真实 native worker crash。
