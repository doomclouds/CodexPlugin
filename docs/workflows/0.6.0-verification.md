# Workflows 0.6.0 验证记录

## 行为与模式选择

新增 `workspaceMode: "local"`，显式 `allowWrite: true` 时，真实 worker 的工作目录为原项目实际目录。修改、构建和测试直接作用于原项目，无须 `workflow_apply`。停止、失败和删除运行均保留已经产生的项目改动；删除清理运行记录、日志和基线等自有数据，不回滚源码。

两种隔离模式继续保留，默认 API 仍为 snapshot；已有运行和库定义不自动迁移。AI 建计划时按用户意图明确选择：只读分析不开放写入；希望立即看到变化的日常开发或修 Bug 选 local；先试验并审查后再决定采用选 snapshot；依赖 Git 历史、提交、子模块维护操作选 git-worktree。位置和写入授权分开设置。

参数弹窗提供模式选择、用途说明和执行范围。没有写入授权的定义不能切换为 local，维护计划只能使用 git-worktree；执行开始后固定模式。主界面显示当前方式，local 差异不提供应用按钮。停止或失败后可以查看实际生成的差异，并说明是本次结束时的记录，不声称实时跟踪之后的手动编辑。

## 生命周期与数据边界

本地模式在运行自有 `local-baseline` 中捕获当前源码，保留既有已暂存、未暂存与未跟踪内容的起点；不初始化或重置原项目 Git。支持非 Git 目录、未产生提交的 Git 项目、linked worktree，以及已初始化和未初始化的子模块。变更清单是相对启动基线观察到的源码差异，不能把外部编辑器同期改动都归因于工作流；Git HEAD、索引、引用、配置和子模块提交语义由检查点覆盖。

同一数据存储中的本地运行全程持有项目锁，并与隔离改动应用共用锁，直到 worker 退出、差异、检查点和状态持久化结束。写任务继续串行；等待项目锁时显示等待阶段，仍可停止，并按运行超时结束等待。这个锁不控制外部编辑器，也不承诺不同数据目录的独立服务之间互斥。

`local-v1` 检查点覆盖项目文件、忽略产物和 Git 语义。运行前核对保留检查点，并在启动新执行前清除旧值；缺失可靠检查点的崩溃记录、外部项目或产物变化会阻止缓存重放，要求检查已有改动并创建新预览。正常停止后原地部分改动保留，恢复时可以复用有效完成前缀。

运行前和每次 worker 派发前核对原项目目录身份及路径。项目与数据目录不能重叠；原项目及已初始化子模块的 Git 元数据也不能依赖当前 Workflows 数据目录，避免删除另一运行时破坏本地项目。本地工作区不能被伪装成隔离工作区，任务不能在 local 中声称使用 worktree 隔离。删除使用单独的自有路径验证，不访问原项目；项目已移动、删除、基线损坏或部分清理已经移除基线时仍可以删除自有数据，越界路径和基线符号链接保持拒绝。

确定性 `operation`、保护目录授权与 MCP 激活仍限 Git 隔离模式。本地任务通过原生 Codex 文件、命令与补丁工具完成通用编程及测试，不扩展父聊天工具和写入授权。

容量限制为源码基线 256 MiB、检查点 2 GiB、单文件 512 MiB、100,000 个文件和 16 层子模块；未注册嵌套 Git 仓库明确拒绝。本地差异保留完整变更文件清单与摘要，文本最多预览 4 MiB，MCP 读取继续使用有界视图。

## 验证

真实 `local-real-smoke.ts --real-workers` 在一次性脏 Git 项目中启动两个实际 gpt-6-luna / max worker：先修复加法错误并运行既有测试，再由只读 worker 独立验证。额外从宿主执行测试，核对实际通过；写 worker 返回前，原项目中已能读到改动。原用户备注、测试文件及暂存条目保留；直接应用被拒绝，删除真实运行数据后项目代码及测试结果保留。该验证未修改用户真实 REA 项目或配置。

新增模块、引擎、协议、模板、面板和删除回归，覆盖原地即时修改、dirty/unborn/linked worktree/子模块、停止恢复、缺失和过期检查点、项目写入锁与隔离应用互斥、动态分支循环与并行写任务串行、模式权限和不可迁移、晚响应、取消表单恢复、删除后保留原项目、部分删除重试等。

开发浏览器通过交互夹具核对模式选择、取消恢复、保存定义、启动参数、执行后固定、只读限制及本地结果无应用按钮；该夹具不是原生 App 验收。

整仓 `npm run check` 通过：478 项检查中 477 通过、1 项默认跳过，另有 18 项可移植性检查；类型、构建及隔离 MCP 包检查通过。最后补充只读选择限制和项目锁等待超时后，再次通过类型、构建、发布结构及 117 项相关引擎和面板检查。本次共新增 44 项回归。
