# Workflows 0.6.6 验证记录

## 修复与边界

上一版本准确捕获了 REA 验收失败的原生原因：`MCP tool call requires approval, but approval policy is never`。用户选择自动审核，而不是为 `rea/binary_session` 设置持续预批准。

0.6.6 的 agent worker 使用 Codex 原生 `approvalPolicy: on-request` 与 `approvalsReviewer: auto_review`，在线程与回合均声明，并在发起模型回合前核对原生返回的有效策略。原沙箱、网络设置、MCP 过滤和逐工具审批配置保留；不改用户全局配置，不写永久 `approval_mode: approve`。不支持该原生策略时关闭执行，不回退为绕过审批。

新预览和新定义默认 `approvalMode: auto-review`。旧记录缺字段继续按 `never` 执行；只有用户明确选择才切换。参数弹窗支持“自动审核”和“禁止审批”。保存选择不启动工作流，运行期间不可更改，取消不覆盖未保存选择；来源模式在外部更新后，取消不会恢复过时的审批模式。

`workflow_preview`、`workflow_update`、`workflow_save_template` 支持保存审批方式；`workflow_resume` 可明确选择后续 worker 的方式，并与重跑节点边界一起生效。普通 `workflow_start` 使用预览中保存的选择。更改模式不改业务脚本，不绕过检查点，不使有效的已完成前缀失效。确定性维护 `operation()` 保持原来的禁止审批方式。

原生审核的开始与完成显示为节点活动。开发日志保存有界脱敏理由，不转存动作原始参数。拒绝、超时或中止会停止当前 worker；模型完成消息不能覆盖拒绝结果，不自动重试或换接口。脚本仍执行其原有异常处理和清理。未知审核状态、来源、身份或需要人工批准、用户输入的请求均关闭执行。

原生语义依据：[自动审核](https://learn.chatgpt.com/docs/sandboxing/auto-review)、[App Server](https://learn.chatgpt.com/docs/app-server) 与 [配置参考](https://learn.chatgpt.com/docs/config-file/config-reference)。本次未覆盖默认自动审核政策。
