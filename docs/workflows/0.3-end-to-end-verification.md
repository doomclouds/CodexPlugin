# Workflows 0.3 端到端验证

验证日期：2026-10-14。以下记录分别描述协议替身、真实执行与当前桌面连接，不能混用。

## 当前验证结果

`npm run check` 通过：类型检查、自包含构建、清单与引用检查、12 项发布可移植性检查、真实 MCP 协议 smoke、134 项运行时／文件／面板／适配器回归。发布包扫描覆盖 49 个文件。普通回归使用明确的测试适配器；维护测试中的 5 项使用真实 CLI app-server 的私有临时配置，未调用模型，也未修改用户真实配置。

`real-protocol-smoke.ts --real-workers` 通过真实 MCP 工具完成以下流程：

1. 创建独立工作流定义与预览，调用 model 可见的 workflow_start，不传 UI lease。
2. 独立 Git checkout 从真实上游拉取，执行明确联网的 npm ci。
3. 真实默认模型 worker 使用原生命令、修改文件与指定 MCP 工具修复一个已有失败测试，返回结构化报告。
4. 独立命令再次执行测试和构建，保留并检查忽略的构建产物；提交仅发生在隔离 checkout。
5. 应用前原项目内容和 HEAD 未变。关闭 MCP 客户端与服务，重建后读取持久化运行。
6. 另一个真实命令流程被停止，等待 actual command 退出。关闭服务，再按明确授权恢复；已完成步骤使用缓存，被中断的安全可重复步骤再次执行。
7. 经 workflow_apply 快进到已经审查的提交，原项目上的独立测试再次通过。

真实 worker 的工具事件包括 `native:commandExecution`、`native:fileChange`、`mcp:workflow_fixture/read_marker`。测试 MCP 的未授权写工具没有被调用。共 7 个维护任务，没有用固定报告代替实际任务结果。

真实只读联网验证另行通过：默认模型执行 native curl 请求官方文档，HTTP 状态为 200，并读取临时 marker；目录仍只有原文件且字节未变。工具事件为 `native:commandExecution`。授权范围未转换为文件写权限。

选择性 MCP 初始化另以真实 owned app-server 验证：现有 REA 配置只开放指定 binary_session 工具，其他已配置服务器全部禁用，实际 inventory 与要求一致。用户原有过滤和审批设置保留，没有修改用户配置。

## 真实测试发现并修复的问题

- config/read 中未设置字段为 null；未经处理传回 thread/start 会转成不正确的 TOML 空字符串。适配器省略 unset 字段；未授权服务器仅传最小禁用表，避免重新序列化无关配置。这不是用户原配置错误。
- 脚本过早标记 completed，差异和检查点尚未形成。现在完成 review 后标记终态，并等待持久化与锁清理后对查询返回终态。
- 总体任务描述变化时旧 agent 结果错误复用。现在使相关缓存失效。
- 跨进程停止先释放运行锁再写回执，可能被误认为 owner 消失。现在等待有界的回执交接。
- 已产生副作用的命令丢响应后，恢复可能重复写入。独立可复现回归中，修复前 effect=2；修复后 effect=1、commandCalls=1，outcome=unknown 且明确拒绝重新发送。步骤默认非幂等，自动重试和未能安全重用结果的重放须声明可安全重复，不能根据命令名称猜测。
- 市场升级删除旧运行文件，已加载服务后续读取 worker 或内置定义可能失败。现在在启动时缓存这两类资源；独立 MCP smoke 删除它们与 panel HTML 后仍可执行和读取定义。

## 发布后的验证边界

GitHub 市场安装、独立新进程加载与当前桌面聊天的已加载工具是三个不同状态。发布后还需对安装目录启动的真实产品 runtime 重跑协议流程，并读取当前聊天能力版本。新进程成功不能证明旧桌面连接已刷新。

单服务器激活写入成功只返回 pending_restart。没有已验证的官方接口让插件安全地选择性重启当前桌面会话的 MCP 连接；不能通过中断整个桌面应用或其他聊天伪造更新完成。真正的连接身份验收在加载新版后执行。

Claude 的研究证据来自指定版本的精确原字节与 REA 静态分析，未运行 Claude 编排代码；未启用的 v2/world 分支与当前普通 Workflow 路径分别记录。插件没有声明实现这些未验证扩展。
