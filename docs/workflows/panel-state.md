# Workflows 面板与状态

`0.2.0` 面板读取真实定义、运行、任务、结果和差异，不生成示例 worker 或固定的测试通过数。开发页面只用于布局验证，原生宿主的新版入口和生命周期需按版本验收。

## 面板区域

| 区域 | 内容与操作 |
| --- | --- |
| 工作流库与编辑区 | 读取定义，选择项目，编辑脚本和 JSON 输入，保存预览或独立定义 |
| 概览 | 项目、脚本、输入、执行状态、已知任务计数、最终结果和可用操作 |
| 任务 | 模式、状态、结果、错误、每次尝试的标识和用量；可取消活跃任务 |
| 差异 | 最终文件差异与冲突，满足条件时应用 |
| 日志 | 调度、worker、命令输出、停止、恢复和应用事件 |

进度展示完成、运行、等待、中断、失败和缓存复用数量，不以未知的最终任务数计算固定百分比。任务是逻辑单元，worker 是一次尝试；缓存复用不新增尝试。

## 独立状态

| 执行状态 | 服务端值 | 含义 |
| --- | --- | --- |
| 待开始 | `draft` | 已保存预览，尚未启动 |
| 运行中 | `running` | 脚本正在调度或等待 |
| 正在停止 | `stopping` | 已请求中断，等待退出与保存 |
| 已停止 | `stopped` | 活跃执行已收尾，等待手动恢复 |
| 执行失败 | `failed` | 脚本未完成；仍保留结果和快照 |
| 执行完成 | `completed` | 脚本与本次 worker 已收尾，可以统一审查 |

任务状态为 `queued`、`running`、`stopping`、`completed`、`interrupted`、`failed`。整次停止把未完成任务记为中断，单任务取消记为失败。并行或流水线可把单项错误转成 `null`，任务失败不必然意味着整次工作流失败。

审查状态为 `unavailable`、`pending`、`ready`；应用状态为 `none`、`applying`、`applied`、`conflict`、`failed`。当前写入运行完成并生成差异后为 `ready`；`pending` 留在类型中，没有独立“已审阅”确认事件。`ready` 只表示可审查，不能代替用户点击应用。

应用冲突、应用失败和执行失败分开。冲突保留当前项目；操作异常或应用中断记为失败，保留日志和事务材料供复查。执行完成不表示当前项目已应用。

## 操作条件

| 操作 | 条件 |
| --- | --- |
| 保存预览或定义 | 宿主连接有效，脚本与 JSON 输入通过校验；不执行 |
| 开始 | `draft`，用户点击当前预览，提交当前版本与租约 |
| 停止 | `running`；请求后等待，停止中不开放恢复 |
| 恢复／继续 | `stopped` 或 `failed`，记录和快照可用，用户触发 |
| 单任务取消 | 活跃任务，其他任务继续由脚本处理 |
| 查看结果与日志 | 数据存在即可查看 |
| 应用改动 | `completed`，存在最终差异，已进入差异页，没有活跃执行且未成功应用 |

版本变化时提示刷新，保存计划修改回到待开始。服务端锁和版本检查保护编辑、执行与应用，不只依靠按钮禁用。

## 宿主连接、关闭与样式

标准 `App.connect()` 建立桥接。面板每 2 秒刷新运行，每 5 秒续租，租约有效期 90 秒。连接初次建立只读取定义和记录，不自动开始。失联展示错误并限制操作，实际状态以服务端为准。

正常 teardown 停止本面板启动的运行并释放租约；无法送达时由租约到期兜底。宿主关闭是否送达事件、是否结束 MCP 服务，需要原生宿主验证。

SDK 的 `applyDocumentTheme`、`applyHostStyleVariables`、`applyHostFonts` 分别应用主题、样式变量和字体 CSS；初次上下文及更新均同步。面板与控件继承宿主字体，代码用宿主等宽字体，字号、行高、字重、颜色、圆角等使用宿主变量，缺失时回退。

[主题检查](../../design-qa.md) 记录开发浏览器的视觉验证。[0.2.0 验证](../workflows-0.2-verification.md) 与 [旧宿主记录](../mcp-app-host-verification.md) 分开；旧 `0.1.4` 原型日志不证明新版原生面板验收。
