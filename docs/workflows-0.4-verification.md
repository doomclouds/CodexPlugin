# Workflows 0.4.0 验证范围

本次面板提供工作流数量与选择、声明参数输入、执行图、启动与停止、插件默认模型和节点模型设置。没有参数声明时可直接启动。宿主主题、字体与字号继续使用 MCP App 样式变量。

主对话的模型与思考深度未由当前 MCP App 宿主公开，因此未配置节点使用运行首启时记录的工作流默认值；插件默认值为空时使用实际 Codex CLI 配置。界面区分请求值、已配置值和实际观测，不把配置回执当作每个推理 turn 的实际模型证明。

## 本机验证

环境：Windows，Node.js 24.18.1，Codex CLI 0.162.1。

- 参数、脚本、定义库与图状态：42 项通过。
- 执行引擎、模型设置与 MCP 路由：34 项通过，包含快照固定、CAS、缓存失效、动态任务身份绑定和固定命令错绑拒绝。
- 适配器：48 项通过；原有真实命令沙箱用例为显式 opt-in，本次没有运行该用例。
- 插件可移植性：16 项通过，无跳过；包含 CRLF 元数据和 Windows 目录 junction 的外部引用拒绝。
- 界面视觉与主要交互：浅色、深色、320px 窄窗口、参数保留、启停、设置与缩放通过。详见 [界面验收](../design-qa.md)。
- 前端控制器、参数与节点设置的最终组合：59 项通过；最终类型检查、运行包构建与隔离 MCP smoke 通过。

一次真实 Codex worker 验证使用独立临时项目和状态目录，声明必填 Bug 链接并原样传入，节点设置为 `gpt-6.1-sol / low`。结果原样返回参数，任务完成；原生配置回执记录 `source=phase`、`provenance=configured`。耗时 13.1 秒，输入 12812 tokens、输出 27 tokens，没有工具调用。验证未更改用户 Codex 配置。

全量 `npm run check` 曾运行，但在 Windows 的旧 Git/子模块夹具出现失败后停止。本次使用定向检查，不将该次全量命令报告为通过。夹具修正保持真实 Git、真实配置协议和平台文件权限检查，不以跳过代替验证。

Windows 私有文件夹具需要先在其自行创建的临时根目录设置私有 DACL，再检查备份与日志继承后的实际权限。该验证前提不代表生产运行时会为任意 `WORKFLOWS_DATA_DIR` 设置 Windows DACL；共享数据目录的隐私隔离未由本次改动建立。

真实配置更新、恢复、回滚、CAS 与快进后激活重试共 5 项通过，所有清理成功。子模块原失败子集的 4 个不同用例均通过：独立 checkout 元数据、未初始化目录与 junction 拒绝、部分应用与私有日志、显式初始化及 gitfile/alternates。最后一项首次遇到 Windows 隐藏 `.git` 文件的覆盖写入限制，改用已有文件句柄截断和写入后单独复验通过；未重跑其余 8 个子模块用例。

原生 Codex 侧栏的最终图标像素和新版面板宿主加载，需要更新插件后重新打开面板核验；开发浏览器截图只证明界面与交互，不证明原生宿主已经切换版本。
