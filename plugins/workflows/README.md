# Workflows

<img src="assets/workflows-icon.png" alt="Workflows 产品图标" width="64" height="64">

`0.5.4` 提供工具栏、横向执行图、节点过程弹窗和彻底删除。脚本由 Agent 创建和维护；每个工作流声明自己的输入项，面板把填写的值传入脚本的 `args`，点击启动后才执行。JavaScript 表达分支、循环、并行和按结果调度；真实 Codex worker 使用原生文件、命令和修改工具，以及本次授权的 MCP。运行可保存、停止、恢复、审查和跨项目复用。

0.5.1 修复删除指纹与表单主题；0.5.2 修复临时 worker 子代理上下文、内置库来源及长错误容错。0.5.3 增加节点显式重试、完整快照恢复检查和只读 Git 状态缓存失效。

0.5.4 修复有效配置仅换字段顺序时，模型目录缓存不能复用的问题。每次仍读取真实配置，真正的值或参数顺序变化仍触发刷新；目录缓存不复用 worker 或工具授权。

需要 Node.js 22 或更新版本、支持 `app-server` 的 Codex CLI 和已有登录。macOS 桌面项目接口还要求启动 Node.js 22.15 或更新版本并支持 `process.execve`。安装版本与当前聊天实际加载的版本分别核对。插件不接管用户登录。

根级 `mcp.json` 使用 Agent Plugin 的标准 stdio 字段，入口为包内启动器。`.codex-plugin/plugin.json` 转发宿主提供的项目接口和运行时环境；macOS 启动器优先使用宿主 Node，并原地替换进程，保留桌面所要求的进程关系。Windows 和普通 CLI 保留原启动方式。安装包不固化管道地址、宿主安装位置或用户目录。

## 使用

主界面保留工作流工具栏和执行图；参数、默认设置、历史运行、差异审查及节点过程在弹窗中查看或修改。用户无需操作大段脚本编辑器。例如 Bug 工作流可以接收编号、链接或补充描述；这些内容是工作流入参，不用于自动选择或生成另一个流程。流程图显示已声明阶段和实际派发任务的状态，动态节点在执行中出现；阶段连线不推断脚本的条件分支、循环回边或任务依赖。

项目对话中的工作流固定属于该项目，已有运行固定绑定创建时的目录，均不能切换项目。全局入口创建新预览时可以选择宿主列出的本机项目；跨项目复用定义须创建独立运行，不移动旧运行或借用其工作区。不从插件目录或历史记录猜测当前项目。接口不可用时显示原因，可以刷新重试。

主题、字体、字号和语义颜色沿用 Codex 宿主变量。“执行设置”可以修改默认模型和思考深度；图中节点的设置按钮直接打开弹窗，保存后覆盖相应阶段或任务，取消或按 Esc 不保存。已开始的运行保存默认配置快照，后续修改不会改写它。模型及支持的深度来自实际 Codex 目录；不可用的配置会明确报错。默认设置使用插件自己的存储，不修改用户的 Codex 全局配置。

当前标准面板接口没有提供主对话模型，未配置时回退到 Codex CLI 的实际配置，界面不会将其标成“继承主 agent”。脚本显式配置和节点覆盖各自保留，优先级为任务节点、阶段节点、脚本、运行默认快照、CLI 配置。节点记录区分计划值与 CLI 已确认的配置，不把它们当作服务端每次推理的物理模型证明。

1. 描述任务、目标项目和允许的操作。Agent 生成脚本、输入与执行范围，通过 `workflow_preview` 保存计划。预览不执行。
2. 已要求执行时，Agent 使用 `workflow_start` 启动；只要求方案时等待执行授权。无需打开面板手写脚本。
3. 用 `workflow_get_run` 或 Workflows 面板查看真实任务、日志与结果。需要停止时调用 `workflow_stop`，它等待实际 worker 退出后保存进度。
4. 重新打开只读取记录。明确要求继续时，Agent 用当前 revision 调用 `workflow_resume`。项目或维护产物变化可能使缓存无法安全重放，此时需要新预览。
5. 执行完成后审查差异和实际验证结果。在已授权的应用范围内调用 `workflow_apply`；也可以在面板中审查并操作。冲突保留当前项目，不覆盖后续编辑。

worker 正常返回不等于结果已通过业务验收。脚本判断结果后失败，普通继续仍保留已完成结果；需要重新检查时，在节点过程弹窗点击“从此节点重试”，或使用 `workflow_resume` 的 `retryFromTaskId`。前面结果保留，该节点及后续结果失效，历史尝试保留。后续已有非幂等命令开始时拒绝重复，须先核对实际效果并生成新计划。

快照恢复核对整个隔离树，包含忽略的产物和 Git 语义；只读 Git 缓存核对提交、分支、索引、引用与本地配置。原项目或隔离区真实变化时不能把旧验证当成新结果。旧快照已经派发过任务却没有检查点时，需要新预览；旧只读运行与 Git 维护运行保留各自兼容路径。

启动先进入 `preparing`，显示环境核对、项目检查和工作区准备等阶段。执行图显示正在读取、修改、运行命令或调用工具的简要动作与耗时；节点过程弹窗说明做了什么、在哪一步失败。开发详情按节点提供有限日志，普通过程视图不展示任务提示词和原始输出。`progressSequence` 用于刷新过程数据，修改或执行操作仍核对当前 `revision`。

断线时保留最后一次读到的记录并暂停操作；重新连接会重建面板租约、读取服务端实际状态，不自动重跑或恢复任务。聊天启动不要求面板租约；面板启动绑定其生命周期，租约丢失会停止对应运行。确认状态后，用户明确继续时再恢复。

## 可表达的任务与工具

脚本通过 `agent()` 请求真实任务，代理可以读取项目、分析代码、运行命令、修改代码并测试。网络授权与文件写入授权分别声明；网络权限不代表发送消息、发布、部署或修改外部数据的业务授权。

外部 MCP 通过 `allowedMcpServers` 声明，`allowedMcpTools` 可进一步指定工具。有效集合保留用户已有的 allow/deny 和审批限制。只读文件沙箱不能让外部 MCP 自动只读；只读 worker 仅开放有只读声明的 MCP 工具，声明仍依赖服务端身份与实际权限。

这些能力足以组合审查与核实、批量处理、按发现修复和测试、联网研究、依赖构建和 Git 维护。具体命令、规则和结束条件是每次工作流的输入，不需要针对每种业务修改插件代码。独立 app-server 不能自动取得父桌面聊天的全部专属 apps、Image Gen、界面控制或交互式权限回调；缺少能力时明确报告，不返回模拟结果。

工作流脚本通过 `parallel` 和 `pipeline` 管理并行及预算。临时 worker 内部的嵌套子代理委派已禁用，避免宿主尝试读取并不存在的持久聊天历史；原生文件、命令、补丁和已授权 MCP 继续可用。worker 保持内存会话，不新增持久聊天数据。

```javascript
export const meta = {
  name: "review-files",
  description: "逐文件审查，再核实和汇总问题",
  phases: [{ title: "审查" }, { title: "汇总" }],
};
const findings = await pipeline(args.files, file =>
  agent(`只读审查 ${file}，返回有证据的问题。`, { label: file }),
);
phase("汇总");
return await agent(`核实并汇总：${JSON.stringify(findings.filter(Boolean))}`);
```

`parallel()` 等待各任务并保留输入顺序，失败项为 `null`；`pipeline()` 按条目独立推进，`null` 停止该条目。直接 `agent()` 失败可以在脚本中捕获。脚本本身运行于 Worker 内的 QuickJS WASM，只使用编排 API；实际工具由代理执行，脚本不直接访问 Node、文件或网络。时钟和随机数禁用，以保持重放确定性。

## 工作流库与跨项目复用

`workflow_save_template` 保存脚本、默认输入、默认范围和限制，不绑定项目、结果或工作区。定义 ID 为 `saved:<meta.name>`，更新需要当前 revision。新定义使用随机初始版本，之后更新递增；删除后重建须重新读取版本，不沿用旧预览。`workflow_list_templates` 和 `workflow_get_template` 读取内置与用户定义。复用时，`workflow_preview` 携带 `sourceDefinition: { id, revision }`，服务端核对版本和脚本并记录来源。对同一个定义，分别指定项目 A 和 B 创建独立运行，缓存和改动互不共享。

保存定义不会开始执行，修改定义不会替换已有运行。当前未提供导入导出或远端同步。运行时项目路径只写入用户的数据目录，不写回发布插件。

## 删除与彻底清理

工具栏操作可以删除当前运行或保存的定义。先预览范围、关联运行、文件数量、大小和阻碍项，再按用户确认的范围删除。定义删除包含通过来源记录可靠关联的运行；旧记录缺少来源时，须明确选择运行 ID，不能仅按名称认定关联。内置定义随插件发布，不能删除其发布文件。

Agent 使用 `workflow_preview_deletion`，传 `kind: "run" | "definition"`、`id`、当前 `revision`；定义可追加明确的 `runIds`。实际删除调用 `workflow_delete`，使用相同目标和最新预览的 `fingerprint`。预览不停止运行、不修改数据；执行、准备、应用中的运行以及仍被配置或其他对象引用的工作区会阻止删除。

成功意味着清除该范围的定义文件、运行记录、日志、结果、隔离工作区、缓存、事务、控制文件和删除元数据，不留下永久墓碑或隐藏副本。删除不会回滚已交付到原项目的文件和提交，也不会移除用户的 Codex 全局设置。快照应用在原项目留下的临时文件，只在拥有可核验的事务记录、文件身份和内容摘要时清理；归属不明的旧临时文件会阻止删除。

失败时返回剩余对象，不报告清理成功。部分删除的记录只保留用于重试的只读摘要和 `deletionTarget`，禁止启动、恢复、修改和应用；重新预览原目标并核对新指纹后继续清理，全部完成后删除这些摘要和元数据。

## 工作区、维护与应用

默认 `workspaceMode: "snapshot"`：写入先在独立文件快照进行，最终按基线检查并应用文件改动。该模式保留已有编辑，不保留完整 Git 历史，不用来拉取分支。

`workspaceMode: "git-worktree"`：为干净 Git 仓库创建包含历史、分支与远端配置的独立 checkout。它拥有自己的 `.git`，不共享原仓库的可写元数据。维护操作使用此模式；完成后核对原分支与 HEAD 基线，只快进到已经验证的提交，不重新查询浮动远端。未提交的源码改动不会被插件自动提交。 Git 子模块按 gitlink 提交和初始化状态记录；已初始化的子模块及嵌套模块在隔离目录保留独立元数据，未初始化的模块保持该状态。需要初始化时由计划声明对应操作和网络范围。文件快照模式遇到子模块会提示使用 Git 模式。审查和恢复覆盖子模块源码、提交与产物；部分应用失败可核验后重试。

可选的 `maintenance.steps` 定义精确 argv、联网范围、超时和最多两次临时网络重试。脚本用 `await operation("step-id")` 执行；未声明的操作拒绝执行。自动重试须明确声明 `idempotent: true`。已开始但结果不确定的非幂等命令不会在恢复时重新发送，须核对实际效果后调整计划。此 API 用于需要确定命令的步骤，普通代理任务不要求声明全部 shell 命令。绝对路径的工具和只读脚本参数按计划执行，写入边界由真实沙箱限制；每次命令的临时目录和 npm/XDG 缓存默认放在隔离工作区，结束后清理，argv、HOME、PATH 和全局配置不被改写。

`maintenance.activation` 可在审查后更新一个已有 stdio MCP 的 command/args。`${WORKSPACE}` 解析为保留的独立 checkout，构建产物经指纹检查。配置前像与私有备份保存在运行目录，以版本 CAS 写入，保留该服务器其他字段；不能安全回滚时明确失败。

仓库及子模块应用、配置激活依次完成。`application: "partial"` 表示已有部分应用，但仍有阶段未完成；可能是子模块应用尚未完成，也可能是仓库及子模块已应用后激活失败。先核对应用记录、实际错误和当前项目状态，再用新读取的 revision 按已有授权重试 `workflow_apply`，核验已完成部分并继续未完成阶段。只有仓库及子模块均已应用、仅激活失败时，重试才只处理激活。配置写入成功不代表当前桌面连接已刷新，状态为 `pending_restart`；应重新加载并核对实际服务身份，再判断是否生效。插件不把新进程探测当成父聊天已更新。

任意外部副作用无法承诺恰好执行一次。中断时应检查实际后置条件、固定提交与产物；非幂等远端写入需使用服务端幂等机制或明确核验，不能盲目重试。

## 保存位置

默认数据根目录由当前用户主目录解析为 `~/.local/state/codex-workflows`，可以通过 `WORKFLOWS_DATA_DIR` 指定。

- `templates/`：用户工作流定义。
- `wf_<id>/run.json`：脚本、输入、范围、状态、任务、尝试、结果与日志。
- 各运行目录：快照或 Git checkout、基线、应用事务、激活备份与控制请求。

这些是用户运行数据，不是发布包的一部分。构建产物被激活引用时，不能删除对应运行工作区。结果和日志可能包含项目内容，应按项目数据管理。

## 验证与开发

```shell
npm run typecheck
npm run build
npm run smoke
npm run smoke:host
npm run smoke:real
node --experimental-strip-types scripts/real-protocol-smoke.ts --real-workers
node --experimental-strip-types scripts/real-repository-smoke.ts --project <repository> --real-commands
```

普通检查不调用模型。`smoke:host` 要求 `CODEX_CLI_PATH` 指向实际桌面 CLI，在临时用户目录和市场中检查宿主加载、21 个工具及 thread/global 面板入口；不发送模型 turn、不修改用户真实配置或安装。`host-loader-smoke.mjs --native-transport` 从宿主签名 Node 启动时，另验证真实项目接口的原生工具目录；本次读取到 54 个工具，含项目和聊天查询。这个探针不等于当前 App 聊天已加载新版，也不能用外部 SDK 的临时 CLI 聊天替代 App 项目归属验收。实际项目查询仍须在 App 重新加载后的真实聊天中核对。

两个真实 worker 验证入口显式调用已登录 Codex 的默认模型；协议验证使用一次性仓库与私有临时配置，检查原生工具、授权 MCP、拉取、联网安装、构建、停止恢复、持久化和审查应用，不修改用户真实 MCP 配置。测试环境目录按系统 API 创建，没有固化开发者目录。

`runtime/` 包含自包含服务与脚本执行器，面板由 MCP App 资源打开。开发用 localhost 预览不代表原生宿主验收。更新后旧进程缓存面板、脚本执行器与内置定义，避免删除旧安装目录导致运行资源失效；新的能力仍须重新加载新版服务后才能使用。
