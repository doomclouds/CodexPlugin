# Workflows

<img src="assets/workflows-icon.png" alt="Workflows 产品图标" width="64" height="64">

`0.11.0` 沿用结构化 JSON 定义与持久执行状态，使用 X6 画布和 ELK 自动布局展示工作流。AI 通过 MCP 创建、更新和保存定义，用户描述需求、填写参数、查看真实进度。执行器直接解释经过校验的流程树；面板显示同一结构与持久节点实例，不再分析 JavaScript 源码推测分支。

0.10.0 起不兼容 0.9.x 及之前的脚本、定义、运行和检查点，不加载、不执行、不迁移旧格式。0.11.0 沿用 0.10.0 的结构化存储格式。旧用户数据不会因为升级被自动删除。进行切换前，应停止旧运行并确认其 worker 已退出；安装成功与当前聊天实际加载新版是两项验证。

## 定义与业务能力

工作流包含顺序步骤、`choice` 多路条件、`parallel` 并行汇合、`map` 集合遍历、`repeat` 有界循环，以及 `try` / `catch` / `finally` 异常与清理结构。基础活动为：

| 节点 | 作用 |
| --- | --- |
| `agent` | 使用真实 Codex worker、原生文件与命令工具、授权 MCP 完成任务 |
| `command` | 执行事先声明的精确 argv、超时与副作用范围 |
| `transform` | 无 I/O 的确定性 JSON 转换 |
| `wait` | 等待明确输入，等待不算执行成功 |
| `subflow` | 调用固定版本或内联的结构化子流程 |
| `expand` | 由模型生成同格式子流程，校验并持久保存后再执行 |

复杂业务在 agent 和 command 内完成；需要在主图展示的条件、循环或并行必须明确写入定义。节点内部工具调用在过程面板查看，不被虚构成额外编排步骤。没有任意 JavaScript 编排、eval、源码反射或自由脚本回退。

定义包含 `schemaVersion: 1`、`name`、`description`、可选 `parameters` 和 `steps`。名称使用小写短横线，节点 ID 全局唯一。表达式支持 JSON 字面量、`{ref:"args.name"}`、`{ref:"steps.inspect.output.changed"}` 和 `{op:"eq",args:[...]}`。`{literal:...}` 保留原样数据。条件必须是 boolean；缺失引用、隐式类型转换、原型键、循环对象、未声明结构和超出预算均被拒绝。

分支和并行各自使用独立的已提交 JSON 数据上下文；项目文件仍是同一执行工作区视图，子节点输出不泄露到外部作用域，外部读取容器的已提交 output。repeat 的 while 是前测，until 是后测，二者不能并用；最大次数始终明确。map 在开始时固定集合及唯一 itemKey，恢复不重新生成集合。模型结果形状、节点验收和业务选路分别处理，合法的“无更新”不应被标成任务失败。

## 创建、保存与更新

AI 首先读取当前宿主实际加载的 `workflow_get_capabilities`，再用 `workflow_get_projects` 确认当前项目。`workflow_preview` 保存校验后的预览，不执行；按已有用户授权，用返回的运行 ID 和最新 revision 启动。

工作流库保存与项目无关的结构、默认输入和默认授权范围。保存和更新采用 revision 冲突保护；更新定义只影响新运行，历史运行冻结原定义快照和 hash。跨项目复用在目标项目创建独立运行，既有运行不能切换项目目录。面板固定当前项目聊天，不提供全局侧栏入口。

工具参数、表达式与完整示例见包内 [Skill](skills/workflows/SKILL.md) 和 [接口参考](skills/workflows/references/runtime.md)。这些说明只引用随插件发布的文件。

## 状态、日志与恢复

每次真实激活都有独立 instanceId，每次活动执行都有 attemptId。循环轮次和 map 项有单独 scope 实例；同一节点在不同轮次的判断、任务、重试和日志不会互相覆盖。subflow 和 expand 的局部节点使用独立 frame 身份展示。计划结构、实例状态和实际跳转事件由服务端投影，前端只负责布局和交互。

面板可查看分支、汇合、循环回边、各轮/各项实例和节点过程。简要过程展示做了什么、当前活动及错误；开发日志按确切实例和 attempt 读取。后台刷新保留参数弹窗、编辑草稿和选择。刷新、服务重启和同一持久快照重放，应得到相同投影。

运行使用独立 SQLite 存储版本，状态、实例、事件和控制游标在事务中提交。稳定检查点核验项目与已提交结果后继续未完成实例，不再从头重放 JavaScript。默认保留当前代码，不自动回滚。文件或产物发生漂移时暂停核对；写入已经派发但结果未知时进入 unknown，先核对真实效果并记录证据，不能盲目重发。

暂停停止新派发并等待当前活动到达稳定点；停止请求取消并等待真实退出。异常清理属于显式 finally，遵循原授权与时间限制，清理成功不覆盖主错误。普通工具错误可在同一 agent 上下文纠正；审批拒绝、中断和未知副作用不能靠自动重试绕过。

## 工作流画布

较大流程默认以可读字号定位入口或当前活动，左下角缩略图提供全局位置；“适应窗口”可查看全图。滚轮和触控板平移，按住 Command / Ctrl 滚动缩放。也可使用缩放、定位选中和定位当前按钮。

循环、并行和子流程按层级容器展示，条件与分支使用明确端口和汇合。节点点击继续打开准确实例和尝试的过程；折叠只改变展示。状态、轮次和选择的更新不会重新排图；结构变化才请求布局，并保留用户视口。

布局在面板拥有的浏览器 Worker 中运行，随面板销毁；没有额外常驻 Node 服务或 CDN 依赖。画布资源和第三方许可均随插件打包。宿主仍需支持面板所需的浏览器功能，安装成功不等于当前连接已经加载新版。

## 权限与工作位置

Run 的 `grants` 明确读写、联网、MCP 服务与工具、工作区类型和审批方式。节点只能缩小授权。默认不允许写入或网络，默认没有用户 MCP。原生 Codex 工具由真实 app-server 提供；父聊天的专有桌面工具、Apps 与隐式凭据不会被继承。

- `snapshot`：隔离文件快照，完成后审查并按授权应用。
- `git-worktree`：独立 Git checkout，适合需要历史、固定提交或子模块的隔离维护。
- `local`：明确授权后直接修改原项目，改动立即生效，无需应用；停止或删除不撤销原项目改动。

只读节点仍使用只读沙箱。模型配置继承工作流默认值，agent 可明确覆盖模型与思考深度。网络和文件写入分别授权；MCP 白名单不代替原生审批。自动审核仍可能拒绝，并且不扩大原授权。新生成的子流程必须在原范围内，不能偷偷增加命令、写目录或联网权限。

## 保存与删除

默认用户数据目录由系统主目录解析为 `~/.local/state/codex-workflows`，可通过 `WORKFLOWS_DATA_DIR` 指定。0.10.0 在独立结构化存储目录中保存 SQLite 数据库与运行自有工作区，不读取旧版 JSON 运行。项目路径只保存在用户运行数据，不写回发布插件。

删除先预览目标、关联运行和自有文件，核对最新指纹后执行。仍在执行、等待退出或有未核对写入效果时先处理真实阻碍。删除只清理所选定义和运行自有数据，不删除原项目、既有用户文件或已交付改动；不自动删除旧版数据。

## 开发与验证

需要 Node.js 22.15 或更新版本、内置 `node:sqlite`、支持 app-server 的 Codex CLI 和已有登录。插件不接管用户登录。运行包自包含，安装无需构建或依赖开发仓库。

```shell
npm run typecheck
npm run build
npm run smoke
npm run smoke:host
npm run smoke:real
npm run prototype:rendering
```

普通 smoke 在隔离安装包中检查 MCP、定义、持久化和纯计算，不调用模型；单元测试中的 driver 是明确标注的替身。真实 worker smoke 需要显式 `--real-workers`，使用一次性项目。宿主加载、模型执行与当前桌面聊天验收分别报告。

UI 通过 MCP App 全屏资源打开；localhost 仅供开发预览。stdio 服务按宿主连接创建，生命周期跟随父进程；同目录的并发模型目录查询合并，不能承诺整个 App 严格只有一个全局 PID。原生 worker 和其授权工具按任务实际启动并清理。

`prototype:rendering` 启动仅用于开发的本地原型与 X6 / G6 对照。运行来自真实状态机，活动明确使用替身，不调用模型或修改用户项目；它不是插件默认打开方式。
