# Workflows

<img src="assets/workflows-icon.png" alt="Workflows 产品图标" width="64" height="64">

`0.8.0` 提供稳定节点检查点、恢复范围预览、执行尝试与历史记录，以及工具栏、横向执行图和彻底删除。脚本由 Agent 创建和维护；每个工作流声明自己的输入项，面板把填写的值传入脚本的 `args`，点击启动后才执行。JavaScript 表达分支、循环、并行和按结果调度；真实 Codex worker 使用原生文件、命令和修改工具，以及本次授权的 MCP。运行可保存、停止、恢复、审查和跨项目复用。

0.5.1 修复删除指纹与表单主题；0.5.2 修复临时 worker 子代理上下文、内置库来源及长错误容错。0.5.3 增加节点显式重试、完整快照恢复检查和只读 Git 状态缓存失效。

0.5.6 增加逐维护步骤的保护目录授权，并修复数据目录别名导致隔离 Git 工作区无法删除的问题；原项目与未声明目录仍受沙箱限制。0.5.5 移除全局侧栏入口，只保留项目聊天使用，并区分结果检查失败和各类停止原因。

0.5.4 修复有效配置仅换字段顺序时，模型目录缓存不能复用的问题。每次仍读取真实配置，真正的值或参数顺序变化仍触发刷新；目录缓存不复用 worker 或工具授权。

需要 Node.js 22 或更新版本、支持 `app-server` 的 Codex CLI 和已有登录。macOS 桌面项目接口还要求启动 Node.js 22.15 或更新版本并支持 `process.execve`。安装版本与当前聊天实际加载的版本分别核对。插件不接管用户登录。

根级 `mcp.json` 使用 Agent Plugin 的标准 stdio 字段，入口为包内启动器。`.codex-plugin/plugin.json` 转发宿主提供的项目接口和运行时环境；macOS 启动器优先使用宿主 Node，并原地替换进程，保留桌面所要求的进程关系。Windows 和普通 CLI 保留原启动方式。安装包不固化管道地址、宿主安装位置或用户目录。

0.6.3 修复 Codex 内部 turn-diff 检查点引用导致的本地恢复误报；项目文件、构建产物及业务 Git 状态仍严格核验。旧记录无法精确校验时可点击“重新检查”创建独立预览，不改写原记录、不自动执行。

0.6.4 修复本地写节点不能写入项目自身 Git 元数据的问题。新建的本地可写预览记录该权限；旧运行保持原执行范围，需新预览才能使用。只读节点、项目外 Git 元数据及未声明的 `.agents`、`.codex` 写入保持原限制。业务脚本和节点无需为此更改。

0.6.5 为失败的 MCP 调用保留有界脱敏开发诊断；成功调用不记录结果载荷。worker 明确区分整体背景与当前任务，不因工具可用就提前完成其他阶段的验收。此提示不替代已有权限校验。

0.6.6 接入 Codex 原生独立自动审核。新预览默认 `approvalMode: "auto-review"`；需要审批的操作交给独立审核器，仍可能被拒绝。旧记录缺少此字段时保持 `never`，不随升级自动切换。参数弹窗可选择“自动审核”或“禁止审批”；现场人工审批和输入请求仍不支持。白名单不代替原生审批，自动审核不扩大已声明的文件、网络或 MCP 范围，不修改用户全局配置，也不永久预批准工具。审核被拒绝、超时或中止时，该 worker 停止并记录原因，不自动重试或绕过决定。

## 使用

主界面保留工作流工具栏和执行图；参数、默认设置、历史运行、差异审查及节点过程在弹窗中查看或修改。用户无需操作大段脚本编辑器。例如 Bug 工作流可以接收编号、链接或补充描述；这些内容是工作流入参，不用于自动选择或生成另一个流程。流程图显示已声明阶段和实际派发任务的状态，动态节点在执行中出现；阶段连线不推断脚本的条件分支、循环回边或任务依赖。

参数弹窗中的审批模式独立于工作区类型、写入和联网设置。选择后保存待开始预览，或在已停止、失败的运行上明确选择并继续；打开弹窗不会执行。Agent 可在 `workflow_preview`、`workflow_update`、`workflow_save_template` 传 `approvalMode: "auto-review" | "never"`；`workflow_resume` 可显式选择后续 worker 的审批模式，省略时保留原记录的行为。普通 `workflow_start` 使用预览中已保存的选择，不接受临时模式覆盖。保存定义会保留该选择，复用时一并传入新预览；更新旧定义省略字段时保留旧模式。更换审批模式不改变业务脚本，不使既有结果或检查点自动失效，也不放宽恢复校验。确定性 `operation()` 命令仍不接入自动审核。

工具栏下拉框分组列出“本项目运行”和“工作流库”。切换到库定义不会隐藏已有运行；同名运行按状态、创建时间和短 ID 区分。选择运行先读取完整详情，不自动创建、恢复或执行；记录较多时可从下拉框继续加载运行摘要。

从项目聊天打开 Workflows。插件只注册聊天入口，不提供主窗口侧栏的全局入口。面板固定使用宿主确认的当前项目，只查询本项目运行，项目目录不能切换；已有运行也保持创建时的目录。本地项目路径在宿主读取侧解析为实际目录，使符号链接项目与运行的目录一致；目录不存在、无法读取或不是目录时，明确报错，不选择其他项目。没有项目归属或接口不可用时，面板显示原因和项目聊天提示，禁用操作，不读取全局运行历史或模型目录。可以刷新重新确认归属。

宿主明确的项目 ID 优先。有些本地 Codex 聊天没有保存项目 ID，但宿主仍提供这个真实调用方聊天的工作目录；服务端只在该目录与本地项目根目录的实际路径唯一、完全相等时确认归属，并返回 `bindingSource: "thread-cwd"`。这不使用插件进程的 `cwd`、工具参数、旧运行或其他聊天，也不通过父目录匹配。无匹配或有歧义时展示具体原因，面板保持禁用，不能手动任选目录代替归属确认。

跨项目复用时，从目标项目聊天载入已保存定义并创建独立运行，不移动旧运行或借用其工作区。Agent 的 `workflow_preview` 等工具仍接受用户明确授权的目标 `projectPath`，不要求先打开面板；这不会改变当前面板的项目归属。不能从插件目录或历史记录猜测用户目标。

主题、字体、字号和语义颜色沿用 Codex 宿主变量。“执行设置”可以修改默认模型和思考深度；图中节点的设置按钮直接打开弹窗，保存后覆盖相应阶段或任务，取消或按 Esc 不保存。已开始的运行保存默认配置快照，后续修改不会改写它。模型及支持的深度来自实际 Codex 目录；不可用的配置会明确报错。默认设置使用插件自己的存储，不修改用户的 Codex 全局配置。

当前标准面板接口没有提供主对话模型，未配置时回退到 Codex CLI 的实际配置，界面不会将其标成“继承主 agent”。脚本显式配置和节点覆盖各自保留，优先级为任务节点、阶段节点、脚本、运行默认快照、CLI 配置。节点记录区分计划值与 CLI 已确认的配置，不把它们当作服务端每次推理的物理模型证明。

1. 描述任务、目标项目和允许的操作。Agent 生成脚本、输入与执行范围，通过 `workflow_preview` 保存计划。预览不执行。
2. 已要求执行时，Agent 使用 `workflow_start` 启动；只要求方案时等待执行授权。无需打开面板手写脚本。
3. 用 `workflow_get_run` 或 Workflows 面板查看真实任务、日志与结果。需要停止时调用 `workflow_stop`，它等待实际 worker 退出后保存进度。
4. 重新打开只读取记录。明确要求继续时，Agent 用当前 revision 调用 `workflow_preview_recovery`，核对复用、重跑及阻碍项，再带返回的 `recoveryFingerprint` 调用 `workflow_resume`。写入项目或维护产物变化时需要新预览；只读项目变化时全部重新读取，不沿用旧结果。
5. 执行完成后审查差异和实际验证结果。隔离模式在已授权的应用范围内调用 `workflow_apply`；也可以在面板中审查并操作。冲突保留当前项目，不覆盖后续编辑。本地模式已直接写入原项目，核对实际文件后完成，不再应用。

worker 正常返回不等于结果已通过业务验收。脚本判断结果后失败，流程图把相关阶段标为“结果检查失败”，已完成 worker 保留执行完成状态；主按钮改为“查看失败原因”，不会静默复用旧结果。顶部只显示错误摘要，完整错误在关联节点弹窗中展开。需要重新检查时，明确点击“从此节点重试”，或使用 `workflow_resume` 的 `retryFromTaskId`；普通工具恢复仍可复用有效完成结果。前面结果保留，该节点及后续结果失效，历史尝试保留。后续已有非幂等命令开始时拒绝重复，须先核对实际效果并生成新计划。

任务完成后的改动审查失败会显示独立的“改动审查”失败卡，已成功任务保留完成状态。全部任务已完成时，主按钮“重试审查”使用普通恢复，回放仍有效的任务缓存后重新生成审查；它不会要求从 worker 节点重跑。如果脚本忽略了某些失败或中断的任务，则显示普通“继续”，恢复可能重跑这些任务。项目和隔离工作区的恢复检查仍然生效。

运行记录保留最多 4 MiB 的差异文本预览，工具读取默认只传其中最多 256 KiB，完整差异继续参与摘要与应用校验。超出预览时显示“仅部分差异预览”、完整差异总字节数及完整 SHA-256；完整变更文件清单保留。部分文本预览不代表已经展示全部变更，应用操作处理完整清单中的变更。

历史运行按摘要分页读取，界面显示已载入数量与总数，可“加载更多运行”；选中后再读取详情，摘要不替代脚本、输入或执行权限。维护审查的产物默认显示当前 20 项及真实总数，使用“下一页产物”每次读取 100 项，并显示当前条目区间；分页不会覆盖主运行的范围、指纹、折叠或滚动位置。默认日志同样按传输预算截取，完整原始运行数据保留在存储中。

动作已经接受但完整详情暂时无法传输时，面板明确显示“操作已接受”和真实状态摘要，再尝试读取详情；详情确认前禁止再次启动、编辑或应用。仍在运行的本项目工作流可以停止，历史和刷新入口继续可用。读取失败不表示动作没有发生，不能据此自动重发。

快照恢复核对整个隔离树，包含忽略的产物和 Git 语义；只读 Git 缓存核对提交、分支、索引、引用与本地配置。原项目或隔离区真实变化时不能把旧验证当成新结果。旧快照已经派发过任务却没有检查点时，需要新预览；旧只读运行与 Git 维护运行保留各自兼容路径。

启动先进入 `preparing`，显示环境核对、项目检查和工作区准备等阶段。执行图显示正在读取、修改、运行命令或调用工具的简要动作与耗时；节点过程弹窗说明做了什么、在哪一步失败。开发详情按节点提供有限日志，普通过程视图不展示任务提示词和原始输出。`progressSequence` 用于刷新过程数据，修改或执行操作仍核对当前 `revision`。

节点过程仅读取有界诊断，任务收尾检查点尚未完成时也可查看；完整执行结果与操作仍等待收尾确认。弹窗合并连续刷新，简要过程和开发日志分别排队，慢响应不会被新进度一直废弃；失败明确显示原因，可点击重试。

断线时保留最后一次读到的记录并暂停操作；重新连接会重建面板租约、读取服务端实际状态，不自动重跑或恢复任务。聊天启动不要求面板租约；面板启动绑定其生命周期，租约丢失会停止对应运行。确认状态后，用户明确继续时再恢复。

## 可表达的任务与工具

脚本通过 `agent()` 请求真实任务，代理可以读取项目、分析代码、运行命令、修改代码并测试。网络授权与文件写入授权分别声明；网络权限不代表发送消息、发布、部署或修改外部数据的业务授权。

外部 MCP 通过 `allowedMcpServers` 声明，`allowedMcpTools` 可进一步指定工具。有效集合保留用户已有的 allow/deny 和审批限制。只读文件沙箱不能让外部 MCP 自动只读；只读 worker 仅开放工作流授权与明确只读工具的交集；没有可用只读工具的服务在该节点禁用，原生只读工具继续可用。写节点保持显式工具授权，用户过滤和审批规则保留；声明仍依赖服务端身份与实际权限。

这些能力足以组合审查与核实、批量处理、按发现修复和测试、联网研究、依赖构建和 Git 维护。具体命令、规则和结束条件是每次工作流的输入，不需要针对每种业务修改插件代码。独立 app-server 不能自动取得父桌面聊天的全部专属 apps、Image Gen、界面控制或交互式权限回调；缺少能力时明确报告，不返回模拟结果。

工作流脚本通过 `parallel` 和 `pipeline` 管理并行及预算。临时 worker 内部的嵌套子代理委派已禁用，避免宿主尝试读取并不存在的持久聊天历史；原生文件、命令、补丁和已授权 MCP 继续可用。worker 保持内存会话，不新增持久聊天数据。

```javascript
export const meta = {
  name: "review-files",
  description: "逐文件审查，再核实和汇总问题",
  phases: [{ title: "审查" }, { title: "汇总" }],
};
const findings = await pipeline(args.files, file =>
  agent(`只读审查 ${file}，返回有证据的问题。`, { label: file }),
);
phase("汇总");
return await agent(`核实并汇总：${JSON.stringify(findings.filter(Boolean))}`);
```

`parallel()` 等待各任务并保留输入顺序，失败项为 `null`；`pipeline()` 按条目独立推进，`null` 停止该条目。直接 `agent()` 失败可以在脚本中捕获。脚本本身运行于 Worker 内的 QuickJS WASM，只使用编排 API；实际工具由代理执行，脚本不直接访问 Node、文件或网络。时钟和随机数禁用，以保持重放确定性。

## 检查点与节点恢复

0.8.0 在首次执行前、稳定节点结束后和整轮收尾时保存检查点。节点结果、真实尝试和同一时刻的项目或隔离工作区摘要共同提交；先写不可变清单，再以持久化运行记录发布引用。并行区间等待所有实际 worker 退出后保存共同进度，不把其他任务仍在写入的中间状态当成独立可恢复节点。保存失败明确标记并停止后续派发，不把没有提交的孤立结果当作有效缓存。

检查点保留当前文件，不提供旧文件回滚，也不是保存后可继续执行的模型会话或脚本内存快照。恢复会从头重放确定性的编排脚本，复用核验通过的前缀结果，再创建 worker 执行未完成或明确重试的节点。原文件里的部分修改、提交和外部工具副作用仍需核对；不能承诺任意外部操作 exactly-once。

面板“继续”“重试审查”和“从此节点重试”先显示恢复预览，列出将复用、重新执行和失效的实际任务，以及阻碍和注意事项。确认“保留文件并恢复”后，服务端在执行锁内重新核对 revision、恢复指纹、当前文件和已提交结果。选择节点对应实际任务 ID，不按阶段名猜测循环中的某次执行。取消、断线、切换运行、项目归属或版本变化会使旧预览失效；操作已接受但详情读取失败时不会自动重发。

Agent 使用 `workflow_preview_recovery({ id, revision, retryFromTaskId? })` 只读检查范围；按已有执行授权调用 `workflow_resume({ id, revision, recoveryFingerprint: preview.fingerprint, retryFromTaskId? })`。目标任务必须与预览相同。`canResume: false` 时先处理真实阻碍，不篡改检查点或指纹；`failureContext.recovery: "new-preview"` 表示需要保留相同范围另建预览，不能反复继续绕过。旧调用可兼容省略指纹，但仍执行后台恢复校验。写入工作区发生漂移时拒绝复用旧结果；只读项目变化时重新执行全部读取，不把旧观察当作当前事实。

`workflow_get_checkpoints({ id, offset?, limit? })` 按页读取历史检查点摘要、真实总数和下一页位置，单页最多 100 项；历史检查点用于核对进度，不能选择任意旧检查点来撤销文件。节点过程可选择实际 attempt，默认展示最新一次，旧失败活动不会混入新的尝试。当前缓存校验失败单独展示，原 worker 完成状态保持真实。

动态分支变短或任务被替换后，旧任务与完整尝试保存到运行自己的历史目录。`workflow_get_task_history({ id, offset?, limit?, taskId? })` 读取摘要；指定 `historyId` 读取某条历史，默认只展示状态和尝试摘要，`detail: "developer"` 提供有界开发详情。旧记录没有 attempt 关联的日志会注明“历史任务日志，未关联具体尝试”，不伪装成某一次的新日志。归档结果不参与当前节点状态或恢复授权。

检查点清单位于该运行的 `checkpoints/`，退休任务位于 `history/`，均为用户数据目录内的运行自有数据；运行记录只保留小型引用和状态。彻底删除运行会一并清理这些目录、临时写入及历史结果，原项目文件和已经交付的改动保留。

## 工作流库与跨项目复用

`workflow_save_template` 保存脚本、默认输入、默认范围和限制，不绑定项目、结果或工作区。定义 ID 为 `saved:<meta.name>`，更新需要当前 revision。新定义使用随机初始版本，之后更新递增；删除后重建须重新读取版本，不沿用旧预览。`workflow_list_templates` 和 `workflow_get_template` 读取内置与用户定义。复用时，`workflow_preview` 携带 `sourceDefinition: { id, revision }`，服务端核对版本和脚本并记录来源。在项目 A 和 B 的聊天中分别载入同一定义，创建各自的独立运行，缓存和改动互不共享。

保存定义不会开始执行，修改定义不会替换已有运行。当前未提供导入导出或远端同步。运行时项目路径只写入用户的数据目录，不写回发布插件。

## 删除与彻底清理

工具栏操作可以删除当前运行或保存的定义。先预览范围、关联运行、文件数量、大小和阻碍项，再按用户确认的范围删除。定义删除包含通过来源记录可靠关联的运行；旧记录缺少来源时，须明确选择运行 ID，不能仅按名称认定关联。内置定义随插件发布，不能删除其发布文件。

Agent 使用 `workflow_preview_deletion`，传 `kind: "run" | "definition"`、`id`、当前 `revision`；定义可追加明确的 `runIds`。实际删除调用 `workflow_delete`，使用相同目标和最新预览的 `fingerprint`。预览不停止运行、不修改数据；执行、准备、应用中的运行以及仍被配置或其他对象引用的工作区会阻止删除。

成功意味着清除该范围的定义文件、运行记录、日志、结果、隔离工作区、缓存、事务、控制文件和删除元数据，不留下永久墓碑或隐藏副本。删除不会回滚已交付到原项目的文件和提交，也不会移除用户的 Codex 全局设置；本地模式的原项目目录和其中所有文件均不属于运行自有数据，不会被删除。快照应用在原项目留下的临时文件，只在拥有可核验的事务记录、文件身份和内容摘要时清理；归属不明的旧临时文件会阻止删除。

失败时返回剩余对象，不报告清理成功。部分删除的记录只保留用于重试的只读摘要和 `deletionTarget`，禁止启动、恢复、修改和应用；重新预览原目标并核对新指纹后继续清理，全部完成后删除这些摘要和元数据。

## 工作区、维护与应用

AI 创建计划时按任务选择模式并配置权限，用户无需手改脚本：明确要求直接开发、修 Bug 并立即看到原项目变化时选 `local`；试验或先看差异再采用时选 `snapshot`；拉取并固定 Git 提交、分支或子模块的隔离维护选 `git-worktree`。只读分析不开写入权限；权限与工作位置分别设置，本地写入运行中的分析节点也可只读。普通编程请求未指定原地且上下文不明确时保留 `snapshot`，API 默认不变。复用已有定义沿用其模式，不自动切换；需要改变时由 AI 说明执行范围并新建预览。

默认 `workspaceMode: "snapshot"`：写入先在独立文件快照进行，最终按基线检查并应用文件改动。该模式保留已有编辑，不保留完整 Git 历史，不用来拉取分支。

`workspaceMode: "local"`：直接在原项目目录读取、修改、运行命令和测试，需要显式 `allowWrite: true`，写入任务仍使用 `{ mode: "write" }`。项目可以带有已有未提交编辑，也可以是普通非 Git 目录；预览不执行，启动后的写入立即生效。共用同一 Workflows 数据目录时，同一项目的本地写入运行串行；外部编辑器与其他数据目录不受此锁协调，不创建隔离副本，不需要也不能应用；`application: "none"` 不表示改动没有发生。停止、失败或删除运行不会撤销或删除原项目文件。差异展示运行基线之后的项目变化，并发用户编辑不能自动归因于工作流。恢复检查本地检查点；项目发生变化或已经执行过 worker 却缺少检查点时，须核对现状并创建新预览。本地编程、构建与测试由通用 `agent()` 使用原生工具完成；确定性预声明命令也支持本地与文件快照模式；配置激活与保护目录授权仍只支持 Git 隔离模式。

`workspaceMode: "git-worktree"`：为干净 Git 仓库创建包含历史、分支与远端配置的独立 checkout。它拥有自己的 `.git`，不共享原仓库的可写元数据。需要 Git 历史交付与配置激活的维护操作使用此模式；完成后核对原分支与 HEAD 基线，只快进到已经验证的提交，不重新查询浮动远端。未提交的源码改动不会被插件自动提交。 Git 子模块按 gitlink 提交和初始化状态记录；已初始化的子模块及嵌套模块在隔离目录保留独立元数据，未初始化的模块保持该状态。需要初始化时由计划声明对应操作和网络范围。文件快照模式遇到子模块会提示使用 Git 模式。审查和恢复覆盖子模块源码、提交与产物；部分应用失败可核验后重试。

可选的 `maintenance.steps` 定义精确 argv、联网范围、超时和最多两次临时网络重试。脚本用 `await operation("step-id")` 执行；未声明的操作拒绝执行。自动重试须明确声明 `idempotent: true`。已开始但结果不确定的非幂等命令不会在恢复时重新发送，须核对实际效果后调整计划。此 API 用于需要确定命令的步骤，普通代理任务不要求声明全部 shell 命令。绝对路径的工具和只读脚本参数按计划执行，写入边界由真实沙箱限制；每次命令的临时目录和 npm/XDG 缓存默认放在隔离工作区，结束后清理，argv、HOME、PATH 和全局配置不被改写。

维护命令确需更新受保护目录时，由 AI 在该步骤预声明最小范围，例如 `protectedPaths: [".agents/skills"]`。路径相对于本次隔离工作区，只允许 `.agents`、`.codex` 内必要且已经存在的真实目录，优先声明最小子目录；不允许绝对路径、上级路径或符号链接及其跳转链。授权只在对应的 `operation` 执行期间生效，不扩展其他命令或 `agent` worker 的权限。面板的范围与维护摘要会显示步骤和授权目录。增减授权属于执行范围变化，须重新创建预览，不能给保留工作区的旧运行追加权限。

`maintenance.activation` 可在审查后更新一个已有 stdio MCP 的 command/args。`${WORKSPACE}` 解析为保留的独立 checkout，构建产物经指纹检查。配置前像与私有备份保存在运行目录，以版本 CAS 写入，保留该服务器其他字段；不能安全回滚时明确失败。

仓库及子模块应用、配置激活依次完成。`application: "partial"` 表示已有部分应用，但仍有阶段未完成；可能是子模块应用尚未完成，也可能是仓库及子模块已应用后激活失败。先核对应用记录、实际错误和当前项目状态，再用新读取的 revision 按已有授权重试 `workflow_apply`，核验已完成部分并继续未完成阶段。只有仓库及子模块均已应用、仅激活失败时，重试才只处理激活。配置写入成功不代表当前桌面连接已刷新，状态为 `pending_restart`；应重新加载并核对实际服务身份，再判断是否生效。插件不把新进程探测当成父聊天已更新。

任意外部副作用无法承诺恰好执行一次。中断时应检查实际后置条件、固定提交与产物；非幂等远端写入需使用服务端幂等机制或明确核验，不能盲目重试。

## 保存位置

默认数据根目录由当前用户主目录解析为 `~/.local/state/codex-workflows`，可以通过 `WORKFLOWS_DATA_DIR` 指定。

- `templates/`：用户工作流定义。
- `wf_<id>/run.json`：脚本、输入、范围、状态、任务、尝试、结果与日志。
- 各运行目录：快照或 Git checkout、基线、检查点清单、退休任务历史、应用事务、激活备份与控制请求。

这些是用户运行数据，不是发布包的一部分。构建产物被激活引用时，不能删除对应运行工作区。结果和日志可能包含项目内容，应按项目数据管理。

npm run typecheck

普通检查不调用模型。`local-real-smoke.ts --real-workers` 在一次性脏 Git 项目中使用真实 gpt-6-luna / max 执行本地修复和独立只读验证，核对原地修改、原用户文件与索引保留、无需应用及删除后代码保留；这不是用户真实项目测试。`smoke:host` 要求 `CODEX_CLI_PATH` 指向实际桌面 CLI，在临时用户目录和市场中检查宿主加载、24 个工具及仅含 thread 的面板入口声明；不发送模型 turn、不修改用户真实配置或安装。`host-loader-smoke.mjs --native-transport` 从宿主签名 Node 启动时，另验证真实项目接口的原生工具目录；本次读取到 54 个工具，含项目和聊天查询。这个探针不等于当前 App 聊天已加载新版，也不能用外部 SDK 的临时 CLI 聊天替代 App 项目归属验收。实际项目查询仍须在 App 重新加载后的真实聊天中核对。

协议和仓库真实 worker 验证入口显式调用已登录 Codex 的默认模型；协议验证使用一次性仓库与私有临时配置，检查原生工具、授权 MCP、拉取、联网安装、构建、停止恢复、持久化和审查应用，不修改用户真实 MCP 配置。测试环境目录按系统 API 创建，没有固化开发者目录。

`runtime/` 包含自包含服务与脚本执行器，面板由 MCP App 资源打开。开发用 localhost 预览不代表原生宿主验收。更新后旧进程缓存面板、脚本执行器与内置定义，避免删除旧安装目录导致运行资源失效；新的能力仍须重新加载新版服务后才能使用。


## 节点内纠错与执行验收

0.7.0 保留普通工具错误后的同节点纠错，支持 `agent()` 使用独立 `accept` JSON Schema 声明成功条件和 `maxRecoveryAttempts: 0..2` 的额外结果校验回合。模型先收到真实工具结果，必要时纠正调用；业务验收不通过时可以在原临时线程继续工作。返回格式与成功条件分开，避免只允许成功的格式迫使模型隐瞒失败。未声明 accept 时不猜测任意 status 字段。默认额外回合为 0，旧流程不会因升级擅自重试；AI 更新计划时应明确采用恢复策略，不默认添加“任何失败立即停止”。

恢复保持原模型、沙箱、联网、MCP 和审批范围，总时限不重置。审核拒绝、取消、原生回合失败和协议异常停止执行，不通过其他工具绕行。节点日志展示恢复过程；校验耗尽后保留最后返回值并标记节点失败。清理后重新抛出原异常可保留 task/attempt/phase 来源，清理节点不会替代真正失败的节点。

`maintenance.steps` 的精确 argv 可通过 `operation(id)` 在显式可写的本地、文件快照和 Git 隔离计划中执行，不需要模型反复生成 Shell/JavaScript 包装。执行器保留退出码、stdout/stderr 与失败原因，临时缓存清理不删除已记录结果。仅 Git 隔离模式支持 activation 和 protectedPaths。确定性命令与模型工具恢复相互补充；插件不能还原任意子程序内部捕获后从未输出的内容。
