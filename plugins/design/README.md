# Design

`0.5.0` 开发预览版，本地设计工作台。使用真实 HTML、React、TSX、CSS 文件作为设计源，由当前聊天的模型直接修改工程。插件通过 MCP App 打开编辑器，预览、源码、选中编辑和导出使用同一份项目修订。

项目格式为 `schemaVersion: 3`，以 `pages` 声明真实页面及其入口、路由，`defaultPageId` 选择默认页。页面与预览尺寸分别选择，共用尺寸也可限定到某个页面。设计令牌直接来自 CSS 源码，`designSystem` 只保存组件目录和说明。不支持旧开发格式，也不自动迁移；遇到不支持的文件会明确报告，不静默改写或删除原文件。

“页面总览”在同一画布比较 1–4 个真实页面，每页可选自己的实际尺寸。每块板独立预览、选择、交互和定位源码；在另一板输入会切换当前页面，AI 与评论上下文跟随该板。进入单页再返回时保留当前编辑器会话的页面组和视图位置。需要不同设计方案时创建不同源码入口与路由。

每个编辑器最多并发编译 2 页、保留 4 个实时 iframe（包含暂时隐藏的板）。预览缓存按 UTF-8 HTML、共享源码注册表和元数据计费，上限 64 MiB；浏览器运行内存与项目源文件另计。超额会明确拒绝或释放未显示板，重新加载被释放的板会重置其临时运行状态。单页编译或运行错误显示在对应板，不替换其他页面。

默认沿用当前宿主聊天及其已加载工具。可选独立 Codex 任务通过本机 `codex app-server` 使用已有 ChatGPT 登录，不要求 API Key，不读取或复制登录令牌。独立目录以本机 Codex 实际返回为准，不能把全部 ChatGPT 网页模型视为可用模型。工具和面板是否可用，以当前宿主实际加载结果为准。

交给当前聊天时保留完整需求，仅附当前页、选中源码身份和有限评论线索，不重复拼入全工程。每个项目各自保留编辑器会话中的需求草稿；准备期间切换项目、页面或修订时不发送旧需求。明确未发送与投递结果未知分别呈现，结果未知时先查看聊天并确认，避免重复发送；准备失败仍提供完整复制内容。

## 使用

1. 调用 `design_get_capabilities`，确认版本和能力；用 `design_code_list` 打开已有工程，或用 `design_code_create` 创建 HTML / React 起点。
2. 调用 `design_open_editor` 打开代码设计编辑器。描述任务后，当前聊天用 `design_code_list_files` 分页发现文件与 hash，按需用 `design_code_read_metadata` 读取页面、组件、评论或说明，再用 `design_code_read_file` 核对相关源码。后续分页锁定首读 revision，修改用 `design_code_update` 提交实际文件与准确身份。
3. 通过 `design_code_preview` 检查编译诊断，用 `design_code_render` 获取真实图像、运行错误与布局信息。检查图片和目标操作后，再报告实际通过的范围。

已有本插件导出的 ZIP，可在编辑器点击“打开 Design 工程”选择文件，或由当前聊天调用 `design_code_import_project`。它保留原始源码、页面与路由、默认页、视口、设计系统和评论，创建新的独立副本，修订从 1 开始；原项目、旧历史和私有源码目录连接不会被覆盖或继承。导入后仍可继续编辑真实源码。

编辑器提供源码、运行预览、元素选择、静态文字与内联样式修改、评论和版本恢复。动态表达式与复杂组件改动由当前模型修改源码，编辑器不会猜测并覆盖未知表达式。所有改动保留项目修订和文件 hash 检查，发生冲突时重新读取并合并意图。

仅评论或设计系统说明等描述性元数据变化，且源码与预览设置完全相同时，编辑器保留正在试用的输入和组件状态。首次为未标记元素建立评论锚点会修改源码；源码、页面或尺寸配置变化及显式刷新仍会重建原型。预览无法确认新修订时会提示并重新编译，不承诺任意运行时状态跨重编译恢复。

评论默认核对已显示页面及明确入口候选；需要查找其他页面中的共享源码时，点击“核对全部页面”按需编译注册表，覆盖项目最多 32 页，后台核对不创建画板。尚未核对、失败或被逐出的注册表保持明确状态，不按旧偏移猜测对象。

已解决评论用状态徽标与边界区分，正文和操作保持可读；长评论与源码路径可完整换行。通过键盘重新打开或标记解决后，焦点保持在同一评论操作，名称随保存状态更新。

当前聊天可按准确评论 ID 或文件读取评论，再用 `design_code_update_comment` 只修改该条正文或状态，保留其他评论、源锚与源码；相同值不增加历史。文件列表和元数据查询分别分页，结构化响应最多 64 KiB，完整条目不会被截断。不要把分页得到的评论子集覆盖整份评论；`design_code_get` 仍可显式读取完整工程，日常局改采用分页与窄读。

设计指导按任务和投入组合：落地页、工作台、数据、编辑内容、品牌、组件、原型等分别处理，支持快改、标准、探索与精修。20 张原创方向卡只作起点，默认仅载入基础规则与摘要，选定方向才载入详情；用户的自由描述、已有品牌和局改范围优先。方向数量不是模板或设计能力上限，也不是视觉质量证明。

设计知识随插件本地发布：排印、表单状态、构图评审和原型微交互各有按需资料；[本地案例索引](skills/design/references/examples.md)提供十套原创案例，覆盖编辑图谱、操作控制台、文字活动、交互产品、展览导览、旅宿计划、材料目录、公共导向、声音探索与独立档案，含宽窄屏截图、设计拆解和自包含 HTML。有技能文件读取能力的当前聊天可先看相关画面与说明，再读所需代码；其他当前聊天可用 `design_get_reference` 获取一个案例的真实参考图、说明与有限源码片段。一次落地选择一个主方向，以已有品牌为默认底座，必要时借一个局部机制并舍弃冲突特征；探索候选分别比较，不混成一页。不要批量加载全库，参考图也不是本次作品的审阅证据。案例不依赖外部知识网站或全局技能，使用原创图示与明确示例内容，字体按系统回退；品牌与配色仍服从用户需求。

## CSS 令牌、真实组件与素材

设计系统面板直接读取 CSS 文件与 HTML `<style>` 块中的真实自定义属性，显示文件、选择器、条件作用域和同名 `var()` 引用。可以筛选文件、分页、定位源码，暂存多项后一次应用到源码；预览和交付随实际 CSS 改变。这里展示的是源码中的同名引用，不计算浏览器级联，也不扫描 JavaScript 动态样式、内联 style 属性或远端样式。

当前聊天可用 `design_code_list_tokens` 读取准确声明身份和文件 hash，再用 `design_code_edit_tokens` 携带当前修订批量更新值。每批最多 100 项，单值最多 16,384 字符；保存原子检查全部身份与 hash，冲突不覆盖后续源码。无法无损定位的声明保持只读；未提交的暂存遇到源码变化时保留文本，须核对最新声明后重新修改。令牌参数和扫描预算见随包代码项目参考。

`design_code_import_directory` 读取用户明确选择的源码目录，创建独立代码项目，不安装依赖或运行项目脚本。普通预览支持内置 React 和项目中的相对模块、CSS、图片与字体；缺少的依赖会返回真实诊断。

已有 React 组件库使用 `design_code_import_components`：明确选择源根目录、组件入口及导出名，以及需要的 CSS、已有 `.d.ts` 和用法说明。可选 `libraryName` 为最多 48 字符的小写字母、数字和单连字符名称，以字母开头，默认 `design-system`。工具用实际静态编译验证导出，将原 TSX/JS/CSS、传递依赖源码、独立图片/字体和发现的许可原文保存到 `components/<libraryName>/`，入口、指南和来源记录以实际返回的 `paths` 为准。

每次导入只追加一个独立命名库；已有库命名空间、输出路径或组件别名冲突时整批拒绝，原有手改、额外文件和其他组件库保持不变。重复导入需选择新的库名及不冲突的组件别名；修改已有组件则直接编辑其真实源码。预览直接编译页面实际引用的源码，无需重建组件 bundle。类型和注释保留，未执行完整 TypeScript 类型检查。

导入会改写真实静态引用为项目内相对路径，不需要原 `node_modules`。无法封闭的动态依赖、require 别名、`new URL`、二级外部 SVG 资源等明确失败；动态资源输入诊断须在接入页面时处理。工具不执行后端、不安装依赖，不保证任意框架或组件库都能迁移。导入后仍须在页面中引用入口并按真实 API 配置组件，完成编译、浏览器运行、视觉和关键交互检查。来源映射、hash 与实际许可文件保存在项目 provenance 中，不能把编译成功当作许可或效果验收。

图片和字体可通过 `design_code_import_asset` 从明确选择的本地文件导入。预览默认限制外部网络；字体、图片与其他资源应在项目或运行包中实际存在。不能用远端链接、占位块或假数据冒充已完成素材与真实服务。

## 验证与模型任务

编译通过、截图生成、模型看图与交互验证分别报告。`design_code_render` 返回实际图像和观察到的运行/布局信息，不自动完成每条操作路径，也不输出客观质量分数。当前模型需要实际查看图片，并借助可用的宿主能力或用户操作核对关键状态；没有证据的部分明确标为未验证。

独立代码任务仅在用户选择时启动。默认总预算为 10 分钟，源码生成、编译、浏览器渲染和截图反馈共用该预算；最多三个同线程模型回合，包括初稿及最多两次修正。超时、权限拒绝或模型错误会明确结束，不自动切换模型或改用 API Key。以任务返回的预算和实际审阅页面为准。

编辑器“案例参考”与 `design_code_request_generation.referenceId` 可选 `auto`、`none` 或案例目录中的一个 ID。自动选择只在任务关系明确时采用一例；局改与保留品牌的请求不强加案例。独立 worker 没有文件、网络或工具权限，由运行时提供所选案例的有界说明、源码摘录与参考图，每轮保持同一快照；它不自行读取技能目录。参考图和实际工作稿截图分别标记，材料投递记录不能代替作品审阅。具体预算和身份字段见代码项目参考。

独立任务的 `completed` 表示代码提案经过其记录的编译、渲染和截图反馈流程，仍未应用。用 `design_code_apply_generation` 按原始 revision 和文件 hash 应用；该状态不等于所有交互、主题或视口都已验证。取消等待所拥有的任务退出。

## 交付与目录同步

代码项目通过 `design_code_export` 导出自包含 HTML、原始源码 ZIP、PNG 或 PDF，可用 `expectedRevision` 锁定已查看修订。ZIP 包含 `source/`、可运行的 `prototype.html` 和项目描述；源码仍保留原有语言与工程结构。PNG/PDF 需要本机 Chromium，可用 `DESIGN_BROWSER` 指定可执行文件。返回项目/修订/页面、字节数、SHA-256 与短期 `artifactId`。原始文件不超过 3 MiB 时以 `delivery: "inline"` 返回字节，更大时以 `delivery: "artifact"` 返回快照身份；编辑器将大文件直接保存到插件数据目录并回显实际路径。宿主不能下载时也可用 `design_code_save_export`，只接受此 `artifactId`，保存同一份原始文件，不重新导出后来保存的工程；取消下载不触发保存。缓存最多 16 项、合计 64 MiB、单件 32 MiB，保留 10 分钟；过期、服务器退出或容量淘汰后明确报错，需要显式重新导出。

`design_code_import_project` 接受二选一的绝对本地 `file` 或规范 `dataBase64`，可选新名称和 `expectedSha256`。只支持当前格式 ZIP，不迁移旧图层数据或把任意源码 ZIP 猜成 Design 工程。压缩包与解压后内容均最多 32 MiB；校验目录结构、CRC、清单和每份源文件实际字节后才保存。导入不运行 `prototype.html`、工程脚本或模型；打开预览时由源码重新编译。宿主仍可能有更小的上传限制，以实际错误为准。

编辑器“源码目录”可以只读导入已有 HTML / React 工程，或为当前项目显式连接目录。导入建立私有字节 hash 基线，不改原目录。检查变化后，可将目录单端变化拉回同一项目，或把项目单端变化写回原目录；双方同文件变化保留冲突，查看两端真实内容后才能明确选择版本。操作继续核对看到的目录 hash 与当前项目修订，旧比较不能覆盖后续保存。未纳入的文件会报告并保留，缺失依赖仍按真实编译结果说明。

目录位置、基线与写入记录存于私有项目记录，不进入可导出的 CodeProject、HTML 或 ZIP。没有自动监听、依赖安装或工程脚本执行。部分写入保留实际已写/待处理项；重开后先重查现场，再显式处理安全变化，不自动覆盖中断后的手工保存。目录写入逐文件完成，外部编辑器不共享插件锁；不能承诺全目录原子，项目撤销也不会自动撤销磁盘修改。

`design_code_write_directory` 写回当前连接目录时复用上述保护；写往其他目录则使用独立同步清单，拒绝覆盖无关文件和外部改动，不把私有连接带到交付目录。源码目录同步不等于任意框架适配或部署。

持久恢复记录仅覆盖已连接目录；向其他目录导出若部分失败，先按返回的实际已写路径审查文件与清单，没有自动恢复或重试入口。

项目和最近历史保存在本地，最多保留 50 版，单项目含历史的保存预算为 96 MiB。`DESIGN_DATA_DIR` 可指定数据目录。

## 当前边界

代码预览与组件导入已有实现，完整视觉保真、任意组件库兼容、所有关键交互与当前宿主效果仍需按实际任务验收，不宣称已全面达到 Claude Design。在线多人协作和云端分享未实现。

代码原型可以包含前端动效；独立 Motion 时间线、视频渲染与 MP4 导出尚未实现。

操作与参数见随包 [Design Skill](skills/design/SKILL.md) 和 [代码项目参考](skills/design/references/code-project.md)。

## 开发

需要 Node.js 22.15 或更新版本，以及 npm。正常检查不调用真实模型：

```shell
npm run typecheck --workspace=@codex-plugin/design
npm run build --workspace=@codex-plugin/design
npm run smoke --workspace=@codex-plugin/design
```

`npm run preview --workspace=@codex-plugin/design` 只用于开发预览；产品入口是 MCP App。运行包自包含，安装无需从开发仓库补依赖。安装更新不等于当前聊天已重新加载。构建和检查不包含安装插件、修改用户配置、提交、推送或部署。
