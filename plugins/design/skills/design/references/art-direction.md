# 艺术指导

从任务、内容与已有系统形成设计判断。用户明确要求和参考优先，其次是项目既有品牌、组件和设计系统，再使用本页规则。局部修改保留无关区域、手动修改和既有视觉语言。方向卡提供例子；用户可以自由描述新的表现方式，不必从某个风格枚举中选择。

## 任务路由

先判断用户要读、操作、比较、理解还是体验什么。一个页面可以组合规则，主任务决定信息结构，附加内容决定需要补哪些专业约束。

| 主任务 | 先确定 | 执行重点 | 常见失败 |
| --- | --- | --- | --- |
| 产品落地页 | 具体价值、主要行动、可用证据 | 用真实演示、产品细节或案例支撑承诺 | 巨型标题和三张卡片代替产品内容；虚构客户评价 |
| 产品工作台 | 对象、高频动作、异常与恢复 | 信息密度、选择、表格、表单和稳定反馈 | 营销式开场挤掉工作空间；只有正常状态 |
| 数据表达 | 数据来源、单位、比较关系与时间 | 形态、尺度、标签、系列身份、筛选与替代读取 | 用装饰图冒充数据，比例失真，筛选后颜色换义 |
| 编辑内容 | 论点、证据顺序、阅读深度 | 正文行长、标题、图注、旁注和出处 | 用卡片摘要代替完整报告 |
| 品牌表达 | 主体、受众、传播目标和真实资产 | 一个可复述的识别关系，强度服从内容 | 换个品牌名仍适用任何项目；缺图却声称摄影完成 |
| 组件与设计系统 | 实际 API、provider、依赖、样式与字体 | 使用同版本真实组件，核对变体和状态 | 猜类名或 prop，重新画一个静态假组件 |
| 任务原型 | 要验证的假设与关键操作 | 实现本地状态或已授权真实能力，并说明边界 | 将模拟、本地保存和外部服务混为一谈 |
| 对比与决定 | 共同维度、证据、条件与代价 | 可比较的结构，清楚的选择影响 | 无依据评分、排名或伪造差异 |
| 机制图解 | 因果、边界、重要变化 | 画真实动作和变化，箭头说明语义 | 几个系统名称方框和无含义箭头 |

组合示例：带图表的产品落地页仍以产品价值为主，但图表必须遵守数据规则；使用已有组件库的工作台需补组件合同；技术报告中的架构图需补机制规则。不要只凭“极简”“复古”等形容词替换任务判断。

## 投入与范围

- **快改 `quick`**：已确认的小范围改动直接完成，复用品牌与结构；核对受影响区域、关联状态和源码冲突。不要为了改文案重新给全页选风格。
- **标准 `standard`**：确定一个内容相关的构图，完成主要任务、必要状态与目标视口；初次检查后最多一轮集中修正，复用已有通过证据。
- **探索 `explore`**：用户需要多方案时，用同一内容、资产和约束给出 2–3 个不同构图。比较阅读顺序、信息密度、主视觉和行动关系，单纯换色不算不同方案。没有要求比较交付时，自行选合适方向继续完成，不强制停轮。
- **精修 `polish`**：先看当前真实画面，选择用户影响最大的几处；每项记录问题、源位置、修复和实际检查结果。最多两轮有依据检查，仍有问题就列明保留项。

`local` 范围锁定非目标区域与既有品牌；`new` 可以形成新构图，但仍服从已有设计系统；`system` 的跨页面调整需要有明确范围。现有品牌不等于每次只能做局改，新建页面也可以继承同一品牌。用户显式任务与投入要求优先于自动推断。

## 设计决策矩阵

| 维度 | 要做的决定 | 可检查的结果 |
| --- | --- | --- |
| 主体特异性 | 选一个真实术语、单位、工序、作品、数据或用户动作进入主要内容 | 换个品牌名后，主要内容仍能说明本项目的具体价值 |
| 字体角色 | 根据正文、展示、数据、操作定义角色；家族数量服从任务 | 中文、混排、长词、行高和回退可读，实际加载结果有证据 |
| 密度与网格 | 连续阅读与快速操作采用不同密度；确定列、行长、间距和共同轴线 | 不机械三卡片，不为凑格子制造空区块，长文本不裁切 |
| 颜色职责 | 背景、文字、行动、状态、系列身份与数量各有角色 | token 有稳定语义，主题与选中/焦点/禁用状态可读 |
| 图像语言 | 图片用于说明、证明、建立语境或承载概念 | 资产真实合法，裁切与图注有内容依据；缺图时诚实降级 |
| 动态与交互 | 明确动作因果、反馈、等待与恢复 | 静止首屏完整，减少动态有替代，不强加滚动劫持或动画库 |
| 内容诚实 | 使用具体文字与可核实证据，说明示例和模拟 | 不编造评价、人数、奖项、精确分数或已连接服务 |
| 状态覆盖 | 根据真实任务选择正常、空、加载、错误、不可用与恢复 | 错误说明解决方法，失败保留输入；不机械堆无关状态画板 |
| 视口与主题 | 根据用户目标决定宽窄屏和明暗模式的必要范围 | 窄屏重排信息与主行动，同一源码不全页缩小；有意单主题也显式处理背景与控件 |
| 源码与系统 | 明确来自已有系统和本次新增的部分 | 组件可运行，依赖与字体随交付包含，局改不损伤无关源码 |

不要将一个固定底色、展示字体、强调色或卡片组合当作所有任务的答案。相反，也不要永久禁止某个字体、颜色或圆角；有明确品牌或内容理由时可以使用。颜色对比与可区分性属于检查问题，不能凭感觉宣称色觉安全。

字体必须来自项目、随包资产或实际可用的系统回退。声明 `font-family` 不证明目标字形已加载。默认离线预览不能假定 CDN、远端字体或外部依赖可用。没有素材时用真实排版和清楚示意完成设计，不把占位块当作图片验收。

## 方向摘要与按需加载

默认只用基础规则、任务信息和方向摘要。只有选定某张卡或确需比较构图时，才读取 [方向卡](direction-cards.md) 对应 ID 的段落；不要把整份卡片库每次全部塞入上下文。卡片包括用途、避免场景、构图、字体角色、色彩角色与关键细节。

| ID | 方向 | 区别 |
| --- | --- | --- |
| `editorial` | 编辑叙事 | 论点、正文、图文和旁注的阅读节奏 |
| `precision` | 精密工具 | 对象、扫描、操作与可信状态 |
| `brutalist` | 直给结构 | 主张、强对比与显露结构 |
| `expressive` | 表达节奏 | 一个视觉比喻统领色彩和空间 |
| `heritage` | 传承工艺 | 真实作品、时间与技艺依据 |
| `organic` | 自然亲和 | 清楚语言、舒缓分组与恢复 |
| `split-demo` | 并列实证 | 承诺与可运行任务演示相互证明 |
| `documentary` | 现场纪实 | 真实场景与过程提供证据 |
| `gallery` | 内容画廊 | 作品比例、序列与索引主导 |
| `swiss-grid` | 结构网格 | 复杂内容的对齐与导航关系 |
| `signal-console` | 状态控制台 | 时间、异常、过期与下一步动作 |
| `scientific-atlas` | 证据图谱 | 共享尺度、标注、来源与不确定性 |
| `data-narrative` | 数据论证 | 一个发现与支撑它的数据证据 |
| `service-blueprint` | 清晰服务 | 输入、步骤、帮助与错误恢复 |
| `comparison-ledger` | 决策对照 | 共同维度、条件与真实代价 |
| `typographic-poster` | 文字主场 | 一条真实文字与空间关系 |
| `modular-play` | 模块游乐 | 一个可理解规则与真实反馈 |
| `material-catalog` | 实物目录 | 整体、材质、规格和变体比较 |
| `quiet-monochrome` | 克制层次 | 少量视觉变量与精确空间 |
| `kinetic-sequence` | 有因动态 | 时间与状态变化解释关系 |

探索同一指定方向时，保持字体和色彩语义，用主要关系、索引入口、行动或证据入口形成构图差异。局改的候选也只作用在授权区域。不要伪造随机执行输出或为显示“差异”破坏已确认品牌。

## 图层与代码的实际边界

图层文档只使用其真实支持的 `navigate/url/toggle` 交互；额外画板可以说明状态，不能声称已经实现 hover、时间线或复杂逻辑。保留稳定 ID，以准确 revision 提交补丁。

代码工程可以使用真实 HTML/React 事件、状态、hover/focus、校验与响应式 CSS。应在浏览器操作关键路径；没有后端、共享存储或外部连接时，明确本地示例状态。保留无关文件，以实际文件 hash 和项目 revision 保护应用。

## 有限且真实的审查

1. 利用已经提供的当前画面与已通过检查，确认主要阅读路径或操作、真实内容与品牌约束。需要基线且尚无画面时再渲染。
2. 检查本次目标视口和主题中的文字、对比、溢出、素材、初始状态和运行错误。快改集中在受影响区域；标准与精修最多两轮有依据检查，修复后只重看关联部分。
3. 对代码工程实际执行本次关键动作并读回状态；结构、截图、模型看图、交互与源码应用分开报告。静态图不能证明提交或保存成功。
4. 无真实渲染就说明视觉未验证，不因 JSON 合法、lint 通过、截图尺寸正确或协议测试通过而声称视觉优秀。预算结束仍有问题，列出保留项和影响，不伪造高分。
