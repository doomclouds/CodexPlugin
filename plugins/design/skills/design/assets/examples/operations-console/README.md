# 港湾：异常值守工作台

原创离线值守产品，12个示例节点、6个分组。主任务是选择异常、核对证据、确认备用通道，再执行有条件的恢复。数据只存在当前页面，没有设备、后台或真实作业连接。

[页面与完整源码](index.html) · [桌面](desktop.png) · [手机](mobile.png) · [许可](LICENSE)

## 哲学：证据先于恢复

值守者需要知道正在处理谁、依据是什么、尚缺哪个条件。将界面视为一条有对象身份的证据链，而非管理员菜单、统计卡与清单的拼装。异常的视觉重量应来自判断责任，不来自红色徽章数量。

这是原创设计立场，不是关于某位大师的史实或权威背书。可以把它应用到其他有条件操作中，但必须重新定义对象、证据、前提和恢复结果，不能只替换节点名字。

## 方法如何进入构图

桌面将12节点压缩为连续选择队列，当前对象占主要工作面。名称与稳定ID先建立身份，心跳、通道延迟、积压和CPU示例序列随后构成证据；右侧按“核验—备用确认—恢复”组织真实控件。对象记录位于同一工作面中，说明操作如何改变当前状态。

顶部深蓝绿仅界定值守会话，纸白平面承担工作。色彩职责是选择、告警和行动；没有通用后台侧栏、四块大统计或卡墙。中文使用系统无衬线，等宽角色只留给ID与时间；普通信息与操作至少12px，列表元数据同为12px。比较靠轴线、行距和数值单位，正常对象保持安静。

手机先呈现当前异常。通过“切换节点”进入完整队列，选择后返回对象并聚焦标题。关键证据保留；详细CPU序列用原生展开收起，给“核验证据”留出明确入口。这是在任务层级上重排，而不是缩小桌面三栏。

## 素材、代码与因果

全部在 [index.html](index.html) 内，无外部图片、字体、库或服务。

- `01 — An incident`、`:root`、`.dashboard`：选择队列与主工作对象的关系。
- `.work-grid`、`.evidence`、`.procedure`：证据与条件行动，禁止让每一块变成等重卡片。
- `02 — Compact rows`：宽窄重排与手机的队列/对象视图。
- `initialNodes`、`statusNames`、`priority`：完整12对象、状态名称和排序职责。
- `function renderList()`：查询、筛选、排序、稳定身份与派生计数。
- `renderDetail()`、`diagnosed`、`backup`、`recovered`：证据、核验与备用确认、拒绝与成功。
- `openList()`、`openDetail()`：手机进入队列及返回对象的可达路径。

CPU图为原创SVG，序列按明确示例规则生成，末点与选中节点的当前CPU一致；不代表实时采样或真实监控。改变对象后图、值和原因一起变化；恢复后对象与记录同步。

## 运行与核对

可按名称、ID或分组搜索，按状态筛选，并选择异常优先或编号排序。`/`打开搜索，`Escape`清空查询；原生`Tab / Enter / 空格`操作按钮、复选框和展开控件。无匹配保留当前条件与选中对象，清除后可继续。

“北区采集02”初始积压14。缺少核验或备用确认时，恢复不执行，也不会偷偷把拒绝记成已核验。完成两项条件后，节点恢复正常、积压置零，正常数8→9、关注3→2、总积压54→40，记录保留同一ID。重置回到最初12个对象。

在实际宽窄画面判断：当前异常是否始终是主体，证据是否先于行动，未满足条件是否清楚，选择与恢复后是否仍知道正在处理谁。若仍像普通后台换标题、各区域同等抢眼、细字难扫，或方法只存在于这份说明里，就应回到设计阶段；算法或功能通过不能替代这一判断。

## 适用、可借与边界

适合设备排查、值守、任务异常与需要可追踪恢复的专业产品。可借稳定身份、证据与动作相邻、条件不足保持原状、操作记录同步，以及手机先处理当前任务再进入队列的方式。

不要搬走示例指标、备用通道剧情或配色去冒充生产系统。真实部署必须增加鉴权、等待、关联读回、失败恢复和审计；本例的本地状态变化不是设备执行结果。没有自动刷新、上传、云端保存或后台调度，刷新即重置。
