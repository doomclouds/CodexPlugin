# 弧光：让光成为可操作的材料

[页面与源码](index.html) · [宽屏主画面](desktop.png) · [窄屏主画面](mobile.png) · [许可](LICENSE)

完整离线目录包括 `index.html` 与 `media/arc-lamp.png`。灯体是内置图像生成能力制作的原创产品概念，带真实 alpha 透明通道；网页光域由代码生成，不是实物测光、生产图或在售商品。没有第三方灯具、字体或摄影资源依赖；系统字体按环境回退。代码、文案与本例生成概念视觉按本目录 MIT 许可提供。

## 哲学与问题

灯具设计的是注意力与空间之间的关系。让光成为可以调节的材料，而不是在产品介绍下方附上一张参数面板。这是本例作者的设计推导，不冒称具名品牌或设计师的原意。

需要解决的是“参数如何成为感受”：如果数值在变化、主体却不动，交互只是工程说明；如果只有漂亮产品图，又看不出输入改变了什么。因此产品弧线、“弧／光”字面与可调光域处于同一个暗场，预设与自定义直接改变这片场景。

## 形式规则与素材

石墨金属弧线是主要物体；分置的中文名给它留出空间。底面近黑 `#171918`、舞台 `#1b1e1b`，正文与操作用清楚的浅色，不用通用紫色霓虹包装。暖冷色由当前输入推导，承担光的状态。

展示名宽屏128px、手机79px；正文14px，数字18px左右，标签与操作至少12px。手机保留完整灯体，随后呈现语义分行的主张与同场景控制。原生 range、场景和主要控制提供44px的手机目标区域；细轨道不等于触控区域只有轨道高度。

制作透明灯体时先明确轮廓与材料，而不是让代码临时手画一个假产品。可借用的提示关系：

> 原创虚构台灯的产品摄影；连续石墨色缎面金属弧线、薄椭圆重底座、可见乳白扩散面与触感旋钮；完整三分之四视角、真实加工边缘与拉丝细节、克制高光；透明背景，不把光束、文字或环境画进灯体资产。

透明原图使物体与网页光域能独立工作。不能把真实品牌照片、生成概念与物理性能混为一谈。

## 从素材到代码机制

| 位置 | 实际机制 |
| --- | --- |
| `ARC_STAGE_START` | 同一暗场中的字面、透明灯体与光域，保留完整轮廓 |
| `.light-beam::before` / `.light-pool` | 子层限定光域，父层柔化边缘；可调落点与范围，不以硬三角形替代光感 |
| `ARC_CONTROLS_START` | 三个原生 range、预设、状态与恢复，直接属于主场景 |
| `ARC_STATE_START` / `render()` | 一个数值模型同时驱动输入、预设身份、颜色、强弱与展开范围 |
| `construction-notes` | 在同一场景说明可见转轴与旋钮；不是虚构的可制造爆炸图 |

亮度改变实际光域透明度与有限的物体明暗，色温改变 RGB 混色，光束改变展开宽度与落点范围。这里是有因果的网页视觉示意，不声称对应真实照度、色温校准或光学模拟。

三个预设分别为专注85%/5000K/42°、松弛55%/3500K/58°、夜读20%/2700K/26°。手动输入脱离预设后明确显示自定义；恢复回到初始专注场景。构造按钮只开关原物体旁的注释，保持焦点与同一视觉语言。

## 迁移与验收

适合产品概念、可交互物体与需要把输入变成可见结果的展示。不适合代替真实硬件控制、测量、人体工学或生产验证。已有品牌、产品资产与真实组件优先；可只借“主体与控制共享场景”的一个关系，不照搬品牌、灯体形状和整套暗色配方。

改图后重新校对发光起点、落点、阴影与完整轮廓；改参数后确认实际主画面改变，而不只更新数字。逐一操作预设、自定义、键盘、构造和恢复；查看手机焦点是否完整、目标尺寸是否可用、暗部是否仍有物体、普通文字是否至少4.5:1。两张 PNG 只展示初始场景，不能代替其他状态和新项目的实际审阅。
